# V5.1.4 开发前：未修复原因分解与候选覆盖率

截至 2026-09-05，重新读取 144 个已揭盲夹具，验证既有输入、源码与双跑预测
哈希后，重新生成 V5.1.2 原始结构提案。此交付先于边缘候选扩展实现。

## 核心发现

268 个应修复错误格中，60 个已正确接受，208 个未修复：

| 未修复类别 | 错误格 | 对应情形 |
| --- | ---: | --- |
| 结构机制没有正确候选 | 12 | 边缘单点 |
| 正确候选存在，但授权证据不足 | 196 | 多数区域受损 |
| 证据通过但被规则异常阻断 | 0 个已证实 | 未找到此类实例 |

三类合计 208；不存在通过标签知道答案后，就认定接受证据充分的做法。
第三类是规则自报通过却不输出修复的可审计异常，不等价于“未证明代码绝无缺陷”。
通过单格门槛仍不等于通过候选分差和原子组门槛。

这修正了下一步假设：**大多数未修复错误并不是缺少正确候选，而是缺少足够的
独立授权证据。** 不能把这 196 格当作降低阈值即可安全修复的样本。

## 接受前候选覆盖率

分母固定为 268 个应修复错误格，公式采用与既有评分器一致的 AST 规范化比较。
“有正确候选”表示候选集合中至少存在一个真值匹配项，不要求排首，也不授权接受。

| 候选来源范围 | 正确候选覆盖 | 比例 |
| --- | ---: | ---: |
| V5.1.2 原始结构提案，含未选中项 | 256/268 | 95.52% |
| 上述提案与 V4 候选的 oracle 并集 | 268/268 | 100% |
| 上述提案与 V5.1.1 候选的 oracle 并集 | 256/268 | 95.52% |
| 最终正确接受修复 | 60/268 | 22.39% |

原始结构提案覆盖：单点 12/12、连续块 48/48、多数受损区域 196/196、边缘 0/12。
V4 提供了全部 12 个边缘正确建议，但这不证明它能安全区分这些错误和合法边缘例外。
oracle 并集是候选空间上限，不是实际 V5.1.3 精选候选档案的直接测量，亦不是精度。

## 证据与分析 QA

- 逐错误格：`results/v514_candidate_audit_v1/error_cells.json`，包含原公式、真值、
  原始提案、passes、原因、接受结果与互斥分类。
- 全部 144 案例：同目录 `cases.json`；控制案例不丢弃。
- 汇总：同目录 `summary.json`；应弃权案例的标签另设分母，不计入应修复覆盖。
- 可重跑工具：`scripts/audit_v514_candidates.py --output <不存在的目录>`。
- 已核对：60 + 196 + 12 = 268；未修复 196 + 12 = 208；256 = 60 + 196。
- 置信结论：Share with caveats。完整夹具标签可支持本轮候选覆盖计算，但不支持
  自然真实表上的覆盖率或安全泛化。真值未进入候选生成函数。

## 对后续实现的约束

先扩展单个边缘单元格的提案，并保存参照出处；默认不能凭单侧多数授权修复。
需要额外的独立参照或明确约束才允许接受；不足时保持复核。
整段/整列以证据不足诊断为主，不放宽原结构规则以强行覆盖 196 个已知答案。
定位器和 V5.1.3 排名不变量保持不变。随后执行开发消融、源码与协议冻结、
新生成数据上的一次确认；新生成同机制数据不等同第三方自然数据验证。
