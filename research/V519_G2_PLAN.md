## 1. 本阶段目标

把 G1 已验证的组件表接入有预算的全局搜索，产生可从原始输入独立回放的
完整唯一性证书。保持全部定位结果、原候选域、批准规则和浮点语义。

G1 已完成 72 个工作簿、104832 个全局赋值的穷举对照；那是研究参照，
尚不能证明 V519 能在默认搜索预算内解决相同问题。G2 必须实际运行预算搜索，
记录完成或拒绝，不能用已保存的穷举答案替代求解。

本阶段提供模块级实验入口与验证器。统一 `api.localize` 的 V519 路由在
G2、G3 均通过后接入；默认版本及旧模型行为保持不变。

## 3. 第一步：确定状态与预算契约

沿用默认上限：节点 10000、叶求值 4096、准备求值 4096、单组件状态 256。
正式实验前固定参数定义与计数边界，不在失败后提高预算取得通过。

| 阶段 | 计量要求 |
| --- | --- |
| 批准及原状态检查 | 记录批准结果；初始约束求值计入准备账本，不遗漏也不重复扣账 |
| 引用图及候选准备 | 记录图节点/边、候选格/选项数；不将图工作量冒充叶求值 |
| 组件表构建 | 传入剩余准备额度；成功按返回计数对账，失败按异常携带计数对账 |
| 全局搜索 | 每个实际访问前缀计一个节点，每次完整赋值约束求值计一个叶求值 |
| 回退 | 沿用同一账本，记录触发原因和回退前消耗；不得重新调用带满额预算的旧顶层诊断 |
| 证书回放 | 单独记录验证耗时/求值及资源上限，不挤入或隐藏在预测搜索计数中 |

同时保存 `satisfaction_calls`、直接 `model.evaluate` 调用和实际底层求值
核对记录；失败前只尝试但未进入求值的调用应单列，不能伪装成成功求值。
测试通过可观测计数器检查正常、异常和回退分支；不使用全局 monkeypatch 作为
生产记账机制。组件前缀节点与旧逐格节点单位不同，报告中明确这种差异。

建议终态：`unique_solution`、`ambiguous_solutions`、`no_solution`、
`budget_exceeded`、`evaluation_incomplete`、`original_satisfies_constraints`，
以及既有批准拒绝状态。引擎和回退原因另列，不能把“未启用组件路径”当作无解。

## 4. 第二步：实现确定性的全局搜索

1. 由原 `_domain` 重建全部格和选项，包括“不改”；禁止使用标签或证书提供候选。
2. 无候选依赖时优先保持 V518 等价优化路径；有依赖时使用 G1 组件表。
   不支持组件优化且仍可完整验证时，使用原候选域的剩余预算穷举。
3. 固定组件顺序、局部赋值顺序和约束检查顺序。首版不引入启发式重排或并行搜索。
4. 用组件界限排除整个前缀子空间，记录排除约束和覆盖原赋值数。
5. 到完整叶时通过 `to_original` 还原原公式赋值，调用原 `_satisfaction`。
   表上的数值和局部约束可行性不能代替该全局最终判定。
6. 每个不同公式赋值独立计解；数值相同仍不能合并。发现第二解即可判为多解，
   此时只报告至少两个解，不自称全空间搜索完成。

只有空间完整覆盖且恰好一个解，才产生联合接受资格。找到一个解后耗尽任何
必要预算仍为拒绝；存在未处理未知求值时不能证明无解或唯一。

组件状态超限、准备预算不足或数值环境不支持属于优化不可用，允许按剩余额度
回退。并集循环可能是保守拒绝，可进入原域验证；若实际赋值出现循环、缺失、
未知或非有限计算，立即保留不完整状态，不以删除该赋值的方式取得唯一性。

## 5. 第三步：设计完整空间证书

证书至少绑定：模型/规则版本、工作簿、文档字节、批准注册表、日期、后端、策略、
可信配置、运行环境、原域、组件顺序及成员/赋值映射。使用稳定结构化编码；
浮点身份用精确表示，不能按显示小数精度舍入。

每个 terminal 是被证明不可行的组件前缀，或已经由原求值器检查的完整叶。
以组件局部状态数为混合进制建立全局编号区间，按确定顺序检查覆盖范围：

```text
start(prefix) = sum(prefix[i] * product(radices[i+1:]))
size(prefix)  = product(radices[len(prefix):])
```

所有 terminal 必须从 0 连续覆盖到原域乘积，不重叠、不缺口。组件域到原域的
双射由重建验证；不能假设混合进制编号等于原逐格字典序编号。
`pruned_states` 计原赋值数量，`evaluated` 计实际完整叶；已完整证明的空间
大小应与二者之和一致。拒绝伪造的完成标记或计数。

证书不能靠保存“唯一答案”或一份表哈希替代空间证明。独立回放必须：

1. 重新验证批准、日期、输入绑定和数值环境，校验外部可信配置。
2. 从模型重建原候选域、图、组件、全部表行及界限，核对赋值身份和成员归属。
3. 校验前缀的类型、长度、选项范围、覆盖及所引用的约束，重新检查每次剪枝。
4. 用原 `_satisfaction` 复算全部保留叶，确认完整且只有一个公式赋值解。
5. 验证接受动作等于唯一赋值中的实际修改，组标识/组大小一致、决策格完整无重复。
6. 用完整定位和候选参考结果核对排名/分数/证据；若该项在外层验证器完成，
   必须作为交付验证的必需步骤并明确记录，不能只核对结果长度。

回放按调用方可信限制约束输入大小、表重建和证书遍历；不能服从证书自报的
超大预算。验证资源不足返回“未验证”，绝不等价于验证成功。

## 6. 第四步：策略与兼容性

`structural` 仅在完整唯一证明后产生新联合接受组；`review_only` 和
`reject_all` 可保留搜索证据，但不产生接受动作。不自动写回工作簿。

批准无效或无约束时不产生新的约束驱动联合接受。若保留旧版 legacy 行为，
必须与相同输入的 V518 动作逐项一致，并单独标记；不能把该路径当成新证书接受。
完整排名和候选档案必须对 v4、v511 两后端逐项一致，不改默认版本。

## 7. 第五步：固定验收实验

先登记 G2 协议，再运行下列队列。G1 输入已揭示，只能作为开发回归。

| 队列 | 核验内容 | 通过条件 |
| --- | --- | --- |
| G1 全部 72 例 | 两后端预算搜索对照保存的完整穷举，并校验原证据哈希 | 原空间/排名不变；接受时必须与参照唯一赋值一致；逐例报告预算状态 |
| 固定最小门槛 | 3 家族×pair/chain×4/8 格×2 个 G1 种子，共 24 个不同工作簿 | 默认预算内全部完成、得到正确唯一解、证书全部回放通过；不能挑成功子集 |
| 多选项与同值 | 81/144 状态；不同公式同值的多解案例 | 解重数不丢失，零错误唯一接受 |
| 全局约束 | 多约束跨组、局部可行但全局不可行、无解与抵消 | 与完整穷举一致，保持原约束满足时的拒绝修复边界 |
| 预算注入 | 各预算恰好耗尽/差一次；找到单解后中断；准备失败再回退 | 无超额，无清零重试，无不完整接受 |
| 求值与策略 | 循环、缺失、未知、非有限、不支持环境、批准无效、三策略 | 明确拒绝或可证明回退，不扩大接受权限 |
| 证书篡改 | 删/复制 terminal、空洞/重叠、错约束、换组/表行/成员/选项、伪造计数、换输入/批准/日期/环境/策略 | 全部拒绝验证 |

24 例是从 G1 固定矩阵预声明的最小预算能力门槛，不代表额外独立样本。
72 例中其他规模即使超预算仍完整报告；不能据此宣称全部 72 例预算求解成功。
零不安全接受和完整空间不变是所有队列的硬条件，不能用低覆盖或全部拒绝掩盖
能力门槛未通过。未完成案例不记作无解。

## 8. 完成条件与执行顺序

执行顺序：状态/预算协议 → 账本与失败回退 → 全局搜索 → 证书与回放 →
策略/完整排名兼容 → 全部预声明实验 → 证据审计与结果报告 → 提交推送。

G2 完成要求：24 例最小能力门槛全部通过；全队列零错误唯一接受；每个接受
证书均独立回放成功；排名/候选/预算检查通过；篡改和失败注入通过。
保存聚焦测试、Ruff、输入/源码/预测哈希、各状态人口和分阶段成本。
提交仅含本阶段明确文件及证据，核对远端；大源快照和大型结果按现有 results 规则保留。

通过后进入 G3：完整小空间差分、失败注入及 192 个已揭示 V518 工作簿的全量
回归。G3 通过后接入统一 API，再进入 G4 的 13 格真依赖里程碑。
G2 不替代后续最终全仓测试、冻结确认、真实工作簿验证，也不宣称 V519 整轮完成。

立即开始的第一项任务：编写并测试预算账本，明确初始检查、组件准备、失败
回退和完整叶求值的扣账位置；用计数器证明预算不能通过回退得到重置。
