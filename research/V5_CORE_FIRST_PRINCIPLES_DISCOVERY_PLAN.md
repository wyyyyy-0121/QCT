# FormulaGuard 主模型研究重置与证据驱动决策计划

日期：2026-08-31
版本：Research Reset v2
状态：当前唯一权威的主模型研究计划；本计划通过前不授权任何继任模型实现

## 1. 这次复盘后的决定

1. `V4-R1` 继续作为唯一冻结主排序器，`V4.2-Review-B` 继续只是第六复核位。
2. `V4.1-PCG`、`V4.3-Semantic`、初代 `V5-Core`、`V5-Core R2` 和
   `V5-PSL` 的既有失败结论全部保留，不改名恢复、不继续调参。
3. 停止以“下一版一定是更强的通用排序器”为前提。新研究先判断单工作簿、无输出
   真值条件下是否还存在可迁移的新增信息，再在三个互斥分支中选择一个。
4. 不创建 `core-reset-c`，发现阶段统一称为 `model-discovery`。只有不依赖 V4 最终
   排名、独立输出完整排名并通过最终盲测的分支，才有资格命名为 `V5-R1`。
5. 旧 `240+120` 继续保留为候选锁后的冻结试用，不作为调参集；新保管人
   `240+120` 在完整预测锁前保持不可见。两者现在都不读取。
6. 未跟踪的 `formulaguard/evidence_portfolio.py` 是中止原型，不是当前模型或证据，
   不进入任何提交。

本次重置的目标不是寻找下一套权重，而是先回答：**当前输入究竟允许我们知道什么，
现有数据又能支持多强的论文结论。**

## 2. 已确认事实，而不是下一模型的假设

| 证据 | 已确认结果 | 可支持的解释 |
| --- | --- | --- |
| Enron 30 事件/25 工作簿 | V4 Top-5 `50.00%`，MRR `0.3825` | 当前最重要的自然错误回顾性证据 |
| 公开 60 错误 | V4 Top-5 `56.67%`，静态锚 `63.33%` | 以注入故障为主的揭晓开发证据 |
| 公开 30 控制 | V5-PSL 行动 `11/30` | 内部恢复不具有错误特异性 |
| 历史 100 | V4 Top-5 `61.00%`，MRR `0.3823` | 人工制题开发证据，不是 100 个已证实独立模板 |
| V4 强证据规则 | 19 个错误案例行动、17 次命中；控制 `0/30` | 存在高精度窄信号，但覆盖不足且不是新模型 |
| V5-Core | 合成锁定集满分，Enron 规则头 Top-5 `46.67%` | 生成机制重合，没有真实迁移优势 |
| V5-Core R2 | 历史 Top-5 `55%`，Enron Full Top-5 `43.33%` | 统一源分数不能跨结构稳定工作 |
| V4.3-Semantic | 合成语义强，合法例外误报 `16.67%` | 语义不一致不能直接等同错误 |
| V5-PSL 修订 | 静态源覆盖充足，只验证 1 个真实源 | 候选和内部恢复都不是主要突破口 |

Phase 0 已审计 220 个事件、147 个来源单元和 137 个结构外层组。这个规模不能按
220 个独立样本训练复杂模型。更关键的是，自然错误证据主要仍是 Enron 30 事件，
公开压力中只有 2 个 Info1 事件具有真实故障性质；Modified EUSES、Integer、历史
100 以及两套 `240+120` 都不能自动代表自然错误分布。

所谓“六个公开语料”也不是六个可互换的定位验证集：FoRepBench 是修复任务，
SpreadsheetBench 是解析压力，Modified EUSES 和 Integer 主要是注入故障，Info1
只有少量真实故障，Enron 才是当前主要自然错误定位语料。今后不再把来源数量写成
六份独立定位证据。

## 3. 为什么此前连续失败

### 3.1 无真值任务包含不可识别案例

只观察一个工作簿时，同一公式可以与多个互相冲突的作者意图相容。正常的孤立汇总、
合法交替公式、多制度区域和大块复制公式，都可能与“异常”拥有相同的可见结构。
依赖图、候选修复和重算结果不能补出不存在的信息。

因此，系统只能报告可观察证据的支持状态，不能把 `identifiable` 当成模型可直接知道
的客观真值。新接口使用：

- `evidence_supported`：存在有独立同伴支持、且明显优于替代制度的假设；
- `ambiguous`：存在多个稳定、合法且相互竞争的制度；
- `unsupported`：没有足够同伴、角色或可计算关系；
- `impact_only`：影响可能很大，但没有足够证据说明更可能写错。

这些是操作性输出状态，不是对作者真实意图的证明。

### 3.2 三个目标被压进了同一个分数

以下输出必须永久拆开：

1. **缺陷证据**：观察公式是否偏离一个可重建角色；
2. **传播影响**：若该格错误，会影响哪些后代、分支和汇点；
3. **修复假设**：哪些同伴支持什么替代公式。

影响大不等于更可能错误，能生成修复不等于修复正确，替换后更平滑也不等于恢复了
作者意图。传播影响只能用于同一风险带内的复核优先级，修复只用于排名后的解释。

### 3.3 先做模型，再用同构数据证明模型

V5-Core、V4.3 和 R2 都在受控生成数据中形成过漂亮闭环，但模型证据与生成器规则
同构。标签物理隔离没有消除机制泄漏。以后必须先做模型无关的信号审计，再授权一个
模型族；合成集只做工程和机制单测。

### 3.4 论文目标混在一起

“超过 V4”“超过 ExceLint”“提高修复准确率”“降低人工行动率”是不同结论，输入、
输出和指标并不兼容。一个最终盲测高分不能同时证明四件事。新计划为每条结论单独
建立证据链。

## 4. 先固定研究问题和评价单位

### 4.1 三个互斥研究问题

按顺序判断，不允许开发中来回切换主指标：

- **RQ-A 完整排名继任：** 在无真值输入上，能否独立生成完整公式排名，并以固定
  五格预算在自然错误和注入错误上稳定超过 V4？
- **RQ-B 选择性复核：** 若通用排名不可行，能否只在证据充分的子集行动，以明确
  的覆盖代价获得比 V4.2 和既有 V4 强证据规则更好的人工复核效用？
- **RQ-C 最小附加信息：** 若无真值信号不足，哪一种最小用户信息能最大幅度消除
  歧义：历史正确版本、一个关键输出格、一次通过/失败标记，还是一条领域约束？

RQ-A 成功才可能产生 `V5-R1`。RQ-B 即使成功也只能是 V4 系辅助模块。RQ-C 是新
输入契约下的另一个研究项目，不能伪装为 V5 补丁。

### 4.2 固定评价单位

任务契约必须分别定义并导出：

- `fault_episode`：一次标注错误事件，可含一个或多个来源格；
- `source_block`：同一错误机制形成的来源区域；
- `workbook_group`：同一工作簿的所有事件；
- `structure_group`：Phase 0 审计得到的近重复外层组；
- `review_action`：模型真正要求用户检查的格或区域。

完整排名、Top-5 审查集合、区域命中、源块覆盖和选择性行动必须分别评分。地址并列
不得冒充证据，同一区域五个近等价格不得冒充五次独立命中。

### 4.3 指标和统计规则

主要指标只从以下集合选择并在运行前冻结：结构组宏 Top-5、MRR、区域命中、源块
覆盖、acted precision、错误源行动覆盖、控制行动率和 risk-coverage。事件宏均值
只能作次要结果。

在任何效果门槛冻结前先做统计功效和离散步长审计。25 个 Enron 工作簿和 30 个最终
模板能够检出的最小差异必须明确计算；若“绝对提升 5 个百分点且区间为正”在计划
样本量下没有足够功效，就应增加独立模板，而不是运行后放宽区间。所有置信区间和
置换检验以结构组为重采样单位。

## 5. 数据证据等级

| 等级 | 数据 | 允许用途 | 结论上限 |
| --- | --- | --- | --- |
| N1 自然错误 | Enron 30、Info1 少量事件 | 失败发现、迁移安全、自然案例 | 当前样本小，只能有限泛化 |
| N2 人工/半人工注入 | 公开 58、历史 100、旧/新 `240+120` | 类型和模板压力、冻结比较 | 不能代表自然错误频率 |
| N3 同源合成 | PropagationBench、V5-Core/V6/R2 内部集 | 工程回归、机制单测 | 不支持真实泛化 |
| U 无源标签语料 | SpreadsheetBench 等 | 解析覆盖、拒绝和性能 | 不支持定位准确率 |

若论文要声称“真实工作簿上普遍优于 V4”，必须在候选冻结前新增一批版本修订可核或
专家确认的自然错误，并将其中一部分保持未见。若无法获得，研究仍可继续，但最终
主张必须限定为人工/半人工注入模板上的改进，Enron 只作有限自然案例。

所有开发拆分继续使用 Phase 0 的结构外层组。错误版与原表、同一工作簿多事件、近
重复模板不得跨折。文件名、语料 ID、源格、错误类型、正确公式和原表均不得进入
预测接口。

## 6. 文献和原创性门

### 6.1 方法身份必须分级

每项方法卡只能使用以下身份之一：

- `original_implementation`：论文对应的原始实现；
- `official_current_implementation`：作者维护的后续官方实现；
- `validated_reimplementation`：用论文样例和中间量验证的忠实复现；
- `idea_level_proxy`：只复用思想的本项目代理；
- `related_work_only`：任务或输入不兼容，只用于相关工作。

当前检查已经确认：旧 ExceLint 仓库依赖 Windows、Excel 和 Visual Studio；官方
`ExceLint-core` 另有可在 Linux 构建的 headless CLI，可输出工作簿分析与排序后的
候选区域。它应称为 `official_current_implementation`，不能自动等同 OOPSLA 2018
原实验版本。CUSTODES、WARDER、SEDMR、AmCheck 和 LaMirage/FLAME 当前没有已确认
可直接运行的原论文实现时，不得声称完成原工具对比。

### 6.2 不实现所有论文

学术比较先按任务兼容性筛选：

- ExceLint：无真值异常区域，优先作为可运行的主要学术基线；
- CUSTODES、WARDER：聚类/检测，只有输出能映射到共同定位单位时才比较；
- AmCheck、LaMirage、FLAME：修复任务，主要作为修复相关工作；
- SEDMR：检测格和 F1，不用它替代源定位 MRR；
- spreadsheet SFL：需要通过/失败或期望输出，只作有 oracle 参照；
- selective prediction：弃权和 risk-coverage 的理论来源，不是新发明。

原实现不可用不阻止内部 V4 继任研究，但永久阻止“已超过该原工具”的表述。

### 6.3 新贡献在写代码前必须能写成一句话

每个候选贡献必须同时回答：

1. 最近的直接前人是谁；
2. 本项目多了哪一项可观察机制，而不是只多了组件组合；
3. 哪个简单基线或消融可以推翻它；
4. 哪类工作簿上预期失败。

无法写清这四项的方向不进入实现。区域、角色聚类、依赖图、修复生成、反事实、
RRF、弃权和多样性选择本身都不作为原创性主张。

## 7. 分阶段执行计划

### Phase 0：状态、任务和功效冻结

本阶段不运行新模型，交付：

1. 一页式当前状态表，明确哪些文档只是历史记录，修正 README 和
   `PROJECT_STATUS.md` 中已经过时的 V5-PSL/“V5-Core 尚未实现”描述；
2. 任务契约，固定事件、区域、工作簿、结构组和行动单位；
3. 数据账本，逐项标记 N1/N2/N3/U、模板关系和可支持的结论；
4. 指标规格和统计功效报告，先判断最终 30 模板是否足以支撑目标效应；
5. 一个研究选择日志，记录以后每次看标签后作出的决定。

**Gate 0：** 输入、输出、评价单位、数据身份、主要指标和可检测效应全部无歧义。
若最终数据规模无法支持目标主张，先修订数据设计，不写模型。

### Phase 1：方法卡与可运行基线

完成 ExceLint、CUSTODES、WARDER、AmCheck、SEDMR、spreadsheet SFL、LaMirage、
FLAME 和 selective prediction 的结构化方法卡。每张卡记录原文输入、输出、任务、
数据、指标、实现、许可证、支持语法和可比结论。

对官方 `ExceLint-core` 只做最小可运行性验证：

1. 固定仓库提交和依赖锁；
2. 在 Linux 构建 headless CLI；
3. 用自带样例和两个项目工作簿验证输入、输出、候选区域顺序和确定性；
4. 定义如何在不伪造分数的前提下映射为区域/单格复核列表；
5. 若无法产生完整排名，只比较其原生检测/复核指标。

**Gate 1：** 每个论文主张都有原文依据、方法身份和兼容指标。Gate 1 只确定能比较
什么，不因某个旧工具无法运行而阻塞后续信号研究。

### Phase 2：失败图谱与原子信号审计

本阶段仍不训练最终模型，也不搜索连续权重。先用既有 V4、V4.3、R2、PSL 静态
结果建立逐结构组失败图谱，然后只检验四个原子问题：

1. **角色替代支持：** 行、列、矩形或依赖角色是否能在不读取标签时提出一个受独立
   同伴支持的替代假设；
2. **制度歧义：** 是否存在多个稳定公式族，能否避免把合法交替制度强压成一个模式；
3. **区域预算：** 五格预算按不同区域/假设去重，是否比同分地址排序救回真实源；
4. **影响分离：** 图后代和汇点信息是否只改善复核效用，而不会冒充缺陷置信度。

每个问题只实现最简单、可解释的无标签探针。探针必须在读取标签前原子写出所有公式
的原始证据、等价类、支持来源和确定排名。必须通过工作表改名、整体平移、无关格式
变化、合法多制度、标签置乱、分片复算和同源同伴去重检查。

评价时严格区分：

- `oracle union`：标签后多个列表的并集，只是信息上限，成本不是五格；
- `oracle selector@5`：标签后挑通道，不可部署，只是上限；
- `fixed selector@5`：规则在训练组固定、外层组只做测试的真实五格方法；
- `selective action`：实际要求检查的格，单独计算精度、覆盖和控制行动。

只有 `fixed selector@5` 或固定选择性规则能授权下一阶段；oracle 上限再高也不能。
外层拆分按结构组，所有阈值和规则只在训练组确定，并增加 leave-one-corpus-out。

**Gate 2A，完整排名可行性：** 固定无标签规则必须在 Enron 和至少一个 N2 队列都
产生净 Top-5 增益，Enron 至少净救回 3 个来自不同工作簿的事件，任一主要队列相对
V4 不下降超过 5 个百分点，并能回收至少一半 oracle 可用余量。该规则不得把 V4
最终排名作为输入；V4 在此只作为比较对象，否则只能申请 Gate 2B。

**Gate 2B，选择性复核可行性：** 固定规则必须同时超过 V4.2 和既有“V4 Top-5
恰好一个 strong”规则，而不只是通过一个绝对阈值；最低仍要求 acted precision
`>=75%`、错误源行动覆盖 `>=30%`、控制行动率 `<=15%`，并满足 Phase 0 冻结的
组级稳定性条件。

2A 通过才可进入分支 A；2A 失败而 2B 通过时只进入分支 B；两者都失败时进入
分支 C。Gate 2 后禁止增加新通道、扩大 Top-k 或在同一数据上继续搜索规则。

### Phase 3：一次性选择研究分支

#### 分支 A：独立完整排名器

只有 Gate 2A 通过时采用。候选必须：

- 不调用 V4 取得最终基础排名；
- 先形成区域/角色假设，再确定性映射为完整单格排名；
- 缺陷证据、传播影响和修复解释分开；
- 对歧义和不支持案例仍输出完整排名，但不强制高置信行动。

这是唯一可能成为 `V5-R1` 的分支。

#### 分支 B：选择性辅助复核器

只有 Gate 2B 通过时采用。它可以使用 V4 排名，但主要输出是行动、拒绝原因和
risk-coverage。它必须比 V4.2 和既有 V4 强证据规则有可复算增量。无论结果多好，
它都属于 V4 系辅助模块，不能称 V5 或声称替代 V4 主核心。

当前证据表明 B 的先验可行性高于 A，但这不是通过结论；既有 strong 规则本身就是
必须超过的基线，不能换名成为“创新”。

#### 分支 C：最小附加信息

若 2A/2B 都失败，停止无真值继任研究。用同一批已揭晓案例比较四种最小信息的边际
价值：一个历史正确版本、一个关键输出格、一次通过/失败标记、一条领域约束。选择
用户负担最小且区分力最大的输入，另立方法名、数据和协议，并直接比较 GoalDebug、
SFL、动态切片和不变量方法。

### Phase 4：候选规格与最小实现

只为选中的 A 或 B 写一个方法规格。规格固定：

1. 最多 6 个通过 Gate 2 的主要证据量；
2. 一个低复杂度、可解释模型族，模型形式在拟合前固定；
3. 区域/结构组外层交叉拟合和固定随机种子；
4. 五格预算、区域去重、并列和不支持语法规则；
5. 行动阈值、风险与影响的使用边界；
6. V4、静态锚、官方当前 ExceLint、单信号和最简单组合基线；
7. 与贡献句一一对应的关键消融；
8. 只允许一次按预登记故障顺序执行的结构修订。

不使用神经网络，不同时实现多个复杂模型后挑最好者，不让候选修复响应反向决定
基础排名。模型复杂度按 137 个结构组而不是 220 个事件限制。

### Phase 5：揭晓开发门

使用 N1/N2 揭晓开发数据，按结构组外层评价。主要比较和效果门槛以 Phase 0 的功效
报告及 Phase 4 预注册为准，至少要求：

- 分支 A 的结构组宏 Top-5 相对 V4 达到预设最小实际差异，配对方向稳定；
- Enron 不丢失 V4 的总命中，并净增来自不同工作簿的命中；
- 分支 B 的行动效用明确超过 V4.2 和既有 strong 规则；
- 任一主要队列不发生超过预设容忍度的退化；
- 控制、合法多制度、解析不支持和多源块分别报告；
- 完整模型相对最简单组合与关键消融确有增量。

一次结构修订后仍失败，终止该分支，不运行旧试用包。

### Phase 6：候选锁与旧试用包

开发门通过后提交候选锁，记录源码、配置、环境、数据清单和输出协议哈希。旧
`240+120` 只运行一次，称为 `frozen revealed-trial`：

1. 不用于参数或模型选择；
2. 使用与开发门相同的主要指标和停止规则；
3. 运行后不修改候选；
4. 若出现明确性能或控制安全失败，不消耗新保管人最终盲测。

### Phase 7：新保管人最终盲测

旧试用通过后才允许：

1. 审计与全部开发、旧试用模板的结构重合；
2. 核验 PUBLIC/SECRET 双归档预承诺；
3. 候选锁后释放无标签 PUBLIC；
4. 以 24 进程生成完整排名并锁定；
5. 锁成功后释放 SECRET，一次评分；
6. 以模板组为单位报告 240 错误和 120 控制。

正式 `V5-R1` 只授予分支 A，并要求达到 Phase 0 证明有统计功效的预设提升、MRR
正向证据、控制安全、合法例外安全和完整性审计。若 30 个模板不足以支持目标结论，
应在接收 PUBLIC 前增加模板，而不是评分后降低标准。

若数据是人工/半人工注入，即使盲测通过，论文也只能声称在独立未见模板的注入错误
上确认，不得自动写成自然业务错误上的普遍优势。

## 8. 论文成果不再押注“必须出现 V5”

论文采用一条主线、三种可能结局：

- **A 通过：** 无真值完整排名继任模型及其独立模板确认；
- **B 通过：** 有覆盖代价的高精度选择性复核，并明确保留 V4 主排序；
- **A/B 均失败：** 无真值源定位的经验可识别性边界，以及最小附加信息的需求。

三种结局都必须以同一任务契约、官方/忠实基线、自然性分层、泄漏审计和负结果为
基础。这样失败不会再被新版本号掩盖，但也不能只靠“审计很严格”代替方法贡献。
最终论文至多主张一个新增机制；其优势必须来自共同任务上的配对结果和消融，而不是
“把前人方法融合起来”。
