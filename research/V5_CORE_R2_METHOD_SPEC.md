# FormulaGuard V5-Core R2 方法规格

状态：阶段B回顾性大型实验前锁定规格
方法名：Dual-Null Causal Attribution（DNCA）  
接口名：`formulaguard_v5_core_r2`

## 1. 研究问题

给定只有公式、常量和依赖关系的工作簿，不提供正确输出、通过/失败测试、错误类型、真实源位置或正确公式，输出：

1. 所有公式的完整源错误排名；
2. 诊断状态；
3. 对进入观测不确定集合的公式给出候选修复、安慰剂显著性和传播解释。

R2不调用V4排名，也不以“正确修复进入候选池”为公式能够获得高基础名次的条件。

## 2. 第一空模型：候选无关的观测源归因

对公式节点 \(v\) 计算无标签观测描述：

- 制度内公式残差、行为残差和局部图残差；
- 后代异常的深度衰减覆盖率；
- 异常是否跨越多个直接分支；
- 异常祖先惩罚；
- 入度、出度、后代规模、公式制度和公式复杂度。

原始观测源分数为：

\[
q(v)=\left(0.55a_1(v)+0.20a_2(v)+0.25P(v)\right)
\left(1-0.75A(v)\right),
\]

其中 \(a_1,a_2\) 是公式、行为和局部图残差中最大及第二大值；\(P\) 是后代恢复潜势；\(A\) 是异常祖先强度。

为每个公式寻找制度类型、公式复杂度、入度、出度和后代数量最接近的公式作为观测对照，得到经验尾概率：

\[
p_{obs}(v)=\frac{1+\#\{u\in M(v):q(u)\ge q(v)\}}
{1+|M(v)|}.
\]

基础完整排名按 \(p_{obs}\) 升序、\(q\) 降序排列。地址只用于保证可复现的稳定顺序，不参与分数。

## 3. 观测不确定集合

反事实计算不处理固定Top-N，也不能从任意低位提升公式。集合 \(U\) 只包含与观测第一名无法可靠区分的节点：

- `p_obs <= max(0.25, best_p_obs + 0.10)`；
- `q >= best_q - max(0.05, 1.4826*MAD(q))`；
- 最多12格。

这些常量只可在回顾性开发阶段按预登记网格调节；新锁定验证后不得改变。

## 4. 第二空模型：匹配安慰剂干预

只对 \(U\) 中的公式生成候选并执行深度干预。候选质量不影响基础观测排名。

对公式 \(v\) 的最佳候选计算：

\[
T(v)=\max_c\left[
\sqrt{\operatorname{clip}(D(v,c)/0.10)\,
\operatorname{clip}(G(v,c)/0.10)}(1-H(v,c))
\right],
\]

其中 \(D\) 是局部净能量改善，\(H\) 是局部或全局副作用，\(G\) 是后代恢复覆盖。几何平均要求局部改善和有向下游恢复同时存在，避免单一的“把特殊公式改得更整齐”或大型扇出节点主导统计量。

安慰剂对照不是同一公式的其他修复，而是观测上匹配的公式，优先执行与最佳候选相同编辑类型的合理候选。得到：

\[
p_{cf}(v)=\frac{1+\#\{u\in M(v):T(u)\ge T(v)\}}
{1+|M(v)|}.
\]

R2不假定两种证据独立，因此不使用Fisher合并。`p_cf`只用于重排 \(U\) 占据的原排名槽位；\(U\) 外公式的相对顺序完全不变。

## 5. 诊断状态

每个工作簿输出以下一种状态：

- `localized`：观测和安慰剂证据均达到冻结门槛，且没有高副作用或并列；
- `review`：存在观测候选，但反事实证据只足以人工复核；
- `abstain_ambiguous`：无观测显著节点、多个节点并列或安慰剂结果不可区分；
- `unsupported_coverage`：解析覆盖或候选覆盖不足，无法做反事实确认。

报警和完整排名分离。即使拒绝报警，仍输出可复核的完整排名。

## 6. 开发与确认数据

### 6.1 回顾性方向筛选集

- Enron 30事件；
- 已揭晓85例；
- 已揭晓480例锁定验证；
- 旧开发、红队和干净表。

允许用于诊断、消融和有限网格调参，所有尝试写入开发日志。这些数据从此不再称为独立或锁定证据。

### 6.2 新机制留出确认集

必须新建且在冻结后才揭晓。划分单位是错误机制与公式变换，而不是行号或种子。至少包含：

- 未见变异机制；
- 源位置跨行、列和工作表；
- 真实工作簿衍生结构；
- 正确候选被故意移除的定位样本；
- 无错误、合法例外、解析不支持和多可疑源场景。

## 7. 预登记开发顺序

1. R2-S：只运行观测源归因，比较候选缺失时的定位稳定性；
2. R2-P：加入匹配安慰剂，但只记录不重排；
3. R2-F：启用不确定集合内重排与拒绝状态；
4. 在全部回顾性集上做一次固定网格选择；
5. 冻结源码、阈值、数据使用记录和Git提交；
6. 在新机制留出集锁定预测并揭盲。

若R2在新确认集不优于V4/V4.3或只在候选覆盖样本上提升，结论必须降级，不再通过同一确认集继续调参。

## 8. 接口隔离

公开函数不得接收或间接读取：

```text
source_cell, error_type, correct_formula, labels,
template_id, instance_id, workbook_filename
```

允许输入只有内存工作簿、候选预算、匹配对照数和已冻结配置。旧V4、V4.x及V5-Core源码与历史结果保持不变。

## 9. 固定消融、候选移除与WCN选择

阶段B一次性输出以下固定比较，不在看到480例结果后临时增删：

1. 无RCR；
2. 无局部边界保护；
3. 无远距离角色复现；
4. 无异常祖先惩罚；
5. DCF改回加法干预；
6. 无匹配安慰剂；
7. 允许反事实在受限计算预算内越过观测不确定集合；
8. 无WCN，强制对每张表给出报警；
9. 候选池保留75%、50%和0%，分别对应移除25%、50%和100%。

WCN只比较`RCR`、`0.80*RCR+0.20*O`和`0.70*RCR+0.30*DCF`。先排除留一法干净误报超过10%的方案，再依次按错误召回更高、干净误报更低和机制更简单选择；最终并列时固定选择`RCR`。

## 10. 阶段B可复现输出

预测进程只读取公开清单和工作簿，完整分片全部写入并通过数量、唯一性和输入SHA-256检查后，父进程才能读取`evaluation_labels.jsonl`。流水线固定生成：

```text
errors/prediction_complete.json
clean/prediction_complete.json
errors/retrospective_summary.json
clean/clean_summary.json
summary.csv
by_error.csv
failure_cases.csv
wcn_summary.csv
selected_wcn.json

```

完成回执与总审计记录Git提交、模型源码、运行脚本、方法规格及三个输入清单的SHA-256。大型运行要求工作区清洁；`--allow-dirty`只保留给Codex的小型工程测试，不能用于论文实验。

## 11. R2-R1：一次有根因记录的修正

原R2的480错误+360干净回顾性实验未通过冻结门槛。失败不是笼统的“分数不够”，而是两个可复核问题：

1. `function_replacement`的Source Top-5为63.75%，而移除远距离角色复现保护的固定消融提升至91.25%；
2. 直接取消保护虽能提升定位，却让合法特殊公式进入干净表高残差区，WCN失去报警召回；此外一例Source第2名公式被无显著性DCF交换至第37名。

R2-R1只实施以下三项离散、可解释修正，不搜索连续权重：

- **自适应例外释放（AER）**：边界与远距离角色保护仍保留；只有某受保护异常的传播潜势相对其制度、公式复杂度和图位置匹配对照达到经验尾概率不高于0.25时，才解除该格的结构保护；
- **保守报警视图**：Source排序使用AER后的残差，但WCN仍使用保护未解除的制度残差，并采用全表最大值；定位和报警不再被迫共用同一个异常统计量；
- **显著性受限DCF**：仅有候选覆盖、`T>=0.03`、`p_cf<=0.20`的格可重排，并只在Source前12名内交换。所有不显著格保持Source顺序。

R2-R1不是在85例、Enron或未来确认集上选择的版本；其选择依据只来自本章已揭晓的480错误+360干净开发层和一个固定的80例函数替换回归切片。该切片上R2-R1 Source Top-5为100%（80/80），Full与Source逐例相同；这一结果只用于授权完整重跑，不作论文结论。
