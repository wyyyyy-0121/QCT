# FormulaGuard model-discovery 任务契约

状态：Phase 0 草案，待 Gate 0 校验后冻结
日期：2026-08-31
权威计划：`research/V5_CORE_FIRST_PRINCIPLES_DISCOVERY_PLAN.md`

## 1. 研究问题

本契约研究的是**无输出真值的静默公式源审查**：给定一个待审查工作簿，系统是否
能用工作簿内部可见证据生成值得复核的公式排名，同时明确拒绝不可识别案例。

契约不把“找到内部规律”“提出可执行修复”或“后代影响很大”当成错误真值。
RQ-A（独立完整排名）、RQ-B（V4 系选择性复核）和 RQ-C（最小附加信息）互斥，
按权威计划中的 Gate 2 结果顺序选择。

## 2. 推理输入

预测函数只能接收一个 `WorkbookModel` 及其可见内容：

- 公式文本和公式单元格地址；
- 常量、缓存值、空值和可读取的格式/标签上下文；
- 可解析的同工作簿依赖边、工作表和区域边界；
- 明确记录的解析能力和不支持语法状态。

下列字段在预测阶段禁止读取或派生：

- 正确公式、原始正确工作簿、错误版/原表配对关系；
- 期望输出、通过/失败测试、源单元格、错误类型和人工标签；
- 语料名称、模板 ID、文件名语义、路径、生成种子和划分名称；
- 任何 `SECRET`、保管人标签或评分后字段。

开发器可以在外层训练组使用已揭晓标签，但不得把标签字段传入预测函数；所有模型
选择、阈值和标准化参数必须记录为训练组确定的固定产物。

## 3. 输出契约

每个可读工作簿都必须输出一个可复算的记录：

1. 覆盖全部受支持公式格的确定性完整排名；
2. 不超过五个**不同公式格**的固定人工审查集合；
3. 每格的 `defect_evidence`、`impact` 和 `repair_hypotheses` 三个分离字段；
4. 每格一个状态：`evidence_supported`、`ambiguous`、`unsupported` 或 `impact_only`；
5. 对不支持语法、缺失特征、并列和多源块的明确原因；
6. 版本、配置、输入哈希、源码哈希和确定性排序规则。

候选修复是解释性假设。它只能在完整排名确定后生成，不能反过来改变基础排名或
把候选与原表的差异当成错误真值。

## 4. 评价单位

所有结果必须同时保留以下键，禁止用一个单位代替另一个单位：

| 单位 | 定义 | 主要用途 |
| --- | --- | --- |
| `fault_episode` | 一次公开标签事件，可含多个来源格 | 事件层次结果 |
| `source_block` | 同一错误机制形成的来源区域 | 区域命中和去重 |
| `workbook_group` | 同一工作簿的全部事件/控制 | 防止同表泄漏 |
| `structure_group` | Phase 0 近重复规则得到的外层组 | 训练/测试拆分和宏平均 |
| `review_action` | 实际要求用户检查的格或区域 | 精度、覆盖和成本 |

完整排名使用单格命中和 MRR；多源事件另报源块覆盖。Top-5 只能含五个不同格，
同一等价区域的多个地址不能计为多个独立证据。选择性行动不计入完整排名的 Top-k。

## 5. 状态的操作性定义

- `evidence_supported`：至少两个独立证据来源支持同一角色假设，且其支持明显超过
  预注册的竞争制度；支持来源不能只是同一复制区域的重复计数。
- `ambiguous`：两个或更多稳定、合法且相互竞争的制度无法在无标签输入中区分。
- `unsupported`：没有足够同伴、依赖角色或可计算关系，或语法超出支持范围。
- `impact_only`：能可靠计算传播后代、分支或汇点影响，但缺陷证据不足；不得因此
  升级成高置信错误行动。

状态表示系统知道的证据边界，不表示作者意图已被证明。控制表中的合法多制度必须
单独报告，不能从总体控制行动率中隐去。

## 6. 固定排名与人工预算

完整排名的并列规则固定为：

1. 先按预注册风险键降序；
2. 再按支持证据强度降序；
3. 再按区域覆盖/假设覆盖键降序；
4. 最后使用规范化工作表序号和 A1 地址作为**仅用于确定性输出的**稳定键。

地址键不得被解释为证据。固定审查预算为五格；区域去重优先于同分地址填充。若
所有候选都处于同一不可区分等价类，必须输出 `ambiguous` 或 `unsupported`，不以
地址顺序伪造优先级。

## 7. 训练、分组与标签隔离

- 外层划分以 `structure_group` 为单位；同一工作簿、错误版/原表和近重复结构不跨折；
- 公开 60 错误与 30 控制的共享原表组必须位于同一外层折；
- 历史 100 没有生产者模板 ID，使用工作簿身份和已审计近重复簇，并披露残余同源性；
- 每个预测分片在任何标签读取前原子写完完整排名；
- 标签置乱、输入哈希变化、缺失分片和重复键都必须使评分器失败；
- `240+120` 旧试用与新保管人盲测在相应锁之前不得被读取。

## 8. 指标契约

主要指标在看结果前冻结为：

- 结构组宏 `Top-5`、`MRR`；
- `region_hit`、`source_block_coverage`；
- `acted_error_precision`、`error_source_action_coverage`；
- 错误和控制分开的 `action_rate`；
- `risk-coverage` 曲线及人工检查成本。

事件宏均值只能作为次要视图。每个指标必须同时报告分母、无支持案例数量、并列规则、
结构组重采样区间和配对净胜/负组数。检测 F1、修复准确率和源定位 MRR 不能互相替代。

## 9. 方法比较边界

`V4-R1` 是主比较基线。ExceLint 只有在固定版本、输入适配和输出映射完成后，才可
以 `official_current_implementation` 身份比较；没有原实现的 CUSTODES、WARDER、
SEDMR、AmCheck、LaMirage 和 FLAME 只能标为忠实复现、思想代理或相关工作。不得把
“组件组合”单独写成原创算法，也不得把未在共同输入上运行的工具称为已超过。

## 10. 晋级条件

Gate 2 前只允许无标签原子探针。Gate 2A 通过后才可写独立完整排名器；Gate 2A 失败、
Gate 2B 通过后只能写 V4 系选择性辅助；两者均失败则转入 RQ-C。

任何候选实现都必须预先固定模型族、最多六个主要证据量、阈值、基线、消融、一次
结构修订机会和停止规则。旧试用包只能在候选锁后运行一次；盲测标签只能在完整预测
锁后释放。

## 11. 论文表述上限

在正式 `V5-R1` 产生前，论文只能写：

- V4-R1 是冻结主模型；
- 历史 V4.x、V5-Core、R2 和 PSL 研究线的正负结果；
- 新方法在明确数据角色和共同指标上的开发或盲测结果。

人工/半人工注入模板上的盲测通过，不自动等于自然业务错误上的普遍优势；自然错误
结论必须单独由可核验自然错误数据支持。
