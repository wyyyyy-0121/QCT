# V4 / V5.2 独立验证结果与模型决策

> 结果产生于预测哈希锁定成功之后。此文件只解释已经锁定的输出，不能用于
> 重新选择 V4 参数、V5.2 规则或后续版本阈值。

## 1. 证据链与数据完整性

- 研究范围：由独立出题人制作的 15 个事件级 `.xlsx` 案例；每个事件计一次，
  不拆分为多个单元格样本。
- 预测先行：`run_v4_v52_blind_lock.cmd --workers 24` 在标签释放前完成；锁定元数据
  记录 15 个工作簿 SHA-256、V4/V5.2 配置哈希、源码哈希和 Git 提交
  `0df637b9677499783957b562156d4c7162cbc71b`。
- 标签后置：评分器验证了锁文件、15 个唯一标签 ID、15 个唯一例外记录 ID 和
  预测 ID 的精确一致性；V5.2 核心排序哈希逐事件等于 V4。
- 审计文件：
  `results/v4_v52_independent_locked/prediction_lock.json`、
  `results/v4_v52_independent_locked/joint_prediction_metadata.json`、
  `results/v4_v52_independent_scored/independent_summary.json`、
  `results/v4_v52_independent_scored/independent_audit.json`。

因此，这是一组可报告的**独立验证案例集**，但样本量为 15，不能写成对任意
电子表格总体的精确率估计。

## 2. 冻结 V4 的事件级定位结果

| 指标 | 点估计 | 事件 bootstrap 95% 区间 |
|---|---:|---:|
| Top-1 | 0.5333 (8/15) | [0.2667, 0.8000] |
| Top-3 | 0.8667 (13/15) | [0.6667, 1.0000] |
| Top-5 | 0.8667 (13/15) | [0.6667, 1.0000] |
| MRR | 0.6726 | [0.4808, 0.8556] |
| EXAM | 0.0758 | [0.0189, 0.1617] |
| 修复精确命中 | 0.7333 (11/15) | [0.5333, 0.9333] |

六类独立错误均有覆盖：reference offset 3 例、range boundary 3 例、function
replacement 3 例、operator 2 例、absolute/relative reference 2 例、copy offset
2 例。V4 在每一类至少命中一个 Top-5；两个 V4 Top-5 漏项分别是
`independent_012`（copy offset，名次 19）和 `independent_015`（function
replacement，名次 28）。

作为量级参照，按每个工作簿的公式数和真实源数计算的精确均匀随机排序期望
Top-5 为 0.0718、MRR 为 0.0685；V4 相对该随机参照的事件级 MRR 差为 0.6041，
bootstrap 95% 区间为 [0.4126, 0.7843]。这只说明结果远高于均匀随机检索，
**不能**替代同一独立集上的 ExceLint、SFL、WARDER 或其他实际基线比较。

## 3. V5.2-B 的辅助审查位结果

V5.2-B 的 `core_top5` 在全部 15 例上逐格、逐顺序等于 V4；因此 V5.2 没有
Top-1、Top-3、Top-5 或 MRR 的“提升”可主张。

- 第六审查位激活：2/15；
- 两次均命中真实源：2/2，救援精确率 100%；
- 两次均是 V4 Top-5 外的新增命中：`independent_012` 和 `independent_015`；
- Review@6 命中：15/15；
- 正确例外公式被错误救援：0/15；
- 预登记辅助模块五个接受门槛全部通过。

可写成：“在这 15 例独立案例集中，V5.2-B 在保持 V4 Top-5 不变的前提下，
将两个 V4 Top-5 外真实源加入额外人工审查位。”

不得写成：“V5.2-B 提升了 V4 Top-5/MRR”或“V5.2-B 在真实表格上达到 100% 准确率”。

## 4. 是否启动 V6

**当前结论：不启动 V6。**

理由不是避免改进，而是当前独立集已经支持冻结 V4 的主定位能力，并支持 V5.2-B
作为严格限定的辅助模块。现在用已经揭晓的 15 个标签继续调主排序，会把独立集
变成开发集，损害最有价值的证据。

只有未来同时满足下列条件，才应开启新的主排序版本：

1. 从另一份未用于确认的开发数据中发现可重复、可解释的失败机制；
2. 提出一个能被否证的机制假设，而不是连续调 GIR 权重；
3. 在新的开发集上冻结 V6；
4. 再由第三方提供另一份全新的独立测试集。

在当前提交窗口内，优先工作应是固定代码、整理结果表和案例、完成论文与答辩，
而不是继续增加版本号。
