# FormulaGuard 论文与实验主体思路（v2执行版）

## 0. 一句话说明项目

FormulaGuard研究的是：**在没有正确输出真值、错误公式仍能正常返回数字时，如何利用公式依赖图、候选修复和反事实干预，定位最早写错并引发下游传播的源公式。**

建议题目：

> 基于依赖图与反事实干预的电子表格静默公式源错误定位方法

英文题目：

> FormulaGuard: Oracle-Free Source Localization of Silent Spreadsheet Formula Errors through Dependency Graphs and Counterfactual Intervention

全文围绕三个关键词：无真值、静默错误、源错误定位。

## 1. 为什么这个题目值得做

大型电子表格中，一个上游公式写错后可能让很多汇总单元格一起出错。普通异常检测容易把下游症状排在前面，却没有回答“最初写错在哪里”。现实中也通常没有一份正确答案可供逐格比较。

FormulaGuard输入一份含公式工作簿，输出：

- 最可能的源错误Top-5；
- 每个候选的可审计分数；
- 建议修复公式；
- 从候选源到受影响汇总的传播路径。

本文不声称依赖图、公式模式或反事实思想本身首创。合理原创点是：

1. 明确定义无真值静默源公式错误定位任务；
2. 提出同时考虑局部异常、反事实改善和源传播责任的GIR；
3. 建立错误类型、传播深度和实际图拓扑均可控的PropagationBench-v2；
4. 用冻结实验、消融、真实语料和失败案例验证方法。

这是一条适合高中生、接近优秀本科课程设计的路线。难点集中在研究设计与证据，而不是堆大模型或复杂理论证明。

## 2. 数据从哪里来

### A层：PropagationBench-v2合成主实验

数据由本项目代码按固定种子生成，不冒充真实业务表。十个模板族按族隔离：

- 开发：预算层级树、销售横向链；
- 验证：库存多表级联、成绩矩阵汇聚；
- 最终测试：实验多表级联、能耗纵向滚动、进度横向链、发票层级树、考勤矩阵汇聚、募捐分叉—汇合。

每份工作簿包含可见的内部一致性检查，但不包含源错误位置或正确公式。真实标签单独写入 `evaluation_labels.jsonl`，只在排序完成后评价。

六类静默错误：引用偏移、区域边界、运算符、聚合函数、绝对引用、复制偏移。传播深度分浅、中、深。偶数版本有较明显局部规律，奇数版本故意减少同类邻居，形成困难条件。

### B层：Enron真实错误外部验证

从官方语料登记的36个错误开始清点。程序支持的样本用于定位评价；不支持、损坏或标签无法映射的样本逐项说明原因。正确公式未知时只评价定位。

### C/D层：可选补充

Modified EUSES可作注入故障扩展；FoRepBench可测显式错误修复；SpreadsheetBench可测复杂工作簿解析。它们不与静默源错误主指标混算。

## 3. 方法主体

1. 解析公式并生成相对引用指纹；
2. 建立单元格依赖图；
3. 计算公式族异常、图结构异常和行为/约束异常；
4. 从方向一致的邻居和平移/小编辑生成候选修复；
5. 把候选临时替换到工作簿并重算，测量异常能量下降；
6. 结合下游影响和源责任得到GIR；
7. 输出Top-5、最佳候选和传播路径。

局部先验：

`P = 0.45*公式异常 + 0.25*图异常 + 0.30*行为异常`

反事实改善：

`D = max(0, (原能量-修复后能量)/原能量)`

传播影响 `I` 归一化到 `[0,1]`，根因因子 `R=0.25+0.75I`。纵向递推首节点再乘边界因子0.25，避免把正常种子公式误报为源错误。

默认分数：

`GIR = 0.35*责任化先验 + 0.50*责任化改善 + 0.10*(D*I) + 0.05*责任化候选质量`

quick只在三组预登记外层权重中选择，不进行任意搜索。full读取冻结配置，结果出来后不能继续微调。

## 4. 实验主体

| 阶段 | 规模 | 目的 | 是否进入论文主结论 |
|---|---:|---|---|
| smoke | 12错误实例 | 检查代码和文件链路 | 否 |
| topology/sparse | 各36错误实例 | 检查结构与困难条件 | 否，只作开发证据 |
| quick | 48错误实例、8干净表 | 选预登记权重、定阈值、冻结 | 只记录开发过程 |
| full | 864错误实例、48干净表 | 最终合成主比较 | 是 |
| Enron | 从36个公开标注错误清点 | 真实外部验证 | 是，单独报告 |
| scaling | 100/500/1000/5000公式 | 性能增长 | 是 |

主比较：Random、Excel-like、Pattern、Graph、Behavior、ExceLint-like、WARDER-like、FormulaGuard。有真值的SFL-Oracle只作辅助参照。

主指标MRR；次指标Top-1/3/5、EXAM、Candidate Coverage@15、修复Top-1、干净表报警率和运行时间。主方法与最强无真值基线做实例级配对bootstrap。只有95%置信区间不跨0才使用“稳定优于”。

必须完成五项消融：去公式、去图、去行为、去传播影响、去反事实干预。结果还要按错误类型、深度、模板族、拓扑和困难条件分层。

## 5. 当前真实进度

### v1历史基线

v1 full已完成864例，核心结果和最终工作簿均完整，不需要重跑。但六个测试族的核心图结构重复，因此只能作为工程基线。

### v2工程证据

- 22项单元测试通过；
- v2 smoke 12/12有效，报告、Excel和完成度审计通过；
- v2 sparse 36/36有效，六个实算结构签名不同；
- sparse上FormulaGuard MRR 0.9253，最强无真值基线0.6560，配对差值95%区间 `[0.1290, 0.4170]`；
- Candidate Coverage@15和修复Top-1均为100%；
- 已消除行为分数与约束残差的重复工作簿求值。

这些是短探针证据，不能替代v2 quick和full。

## 6. quick通过与冻结门槛

- 有效率至少95%；
- Candidate Coverage@15至少90%；
- 干净表报警率不超过25%；
- 错误召回率至少80%；
- MRR不低于最强无真值基线；
- 四个族至少三个不落后；
- 任一消融不得比完整模型高出0.02以上；
- 至少一组预登记权重通过阈值门槛。

通过后冻结权重、阈值、候选数、Git提交和核心代码哈希。full出现结果后不再调整模型核心或参数。

## 7. 从现在到提交的执行顺序

1. Codex完成v2文档一致性、性能优化和全部短测试；
2. 用户运行v2 quick；
3. Codex检查门槛，必要时只做一轮有记录修改；
4. 用户重新运行quick，Codex冻结并记录版本；
5. 用户运行v2 full、敏感性、性能和LibreOffice；
6. 整理Enron全部36项并运行外部验证；
7. Codex生成20—25页论文初稿、表格和图；
8. 完成引用核对、Word排版、三分钟演示和答辩问题清单；
9. 做最终复现性、AI使用披露和提交材料审计。

用户只运行大型命令。短测试、报错修复、结果分析和文档生成由Codex负责。

## 8. 银奖导向的最终证据要求

- v2 full覆盖六类错误、三档深度和六种实际拓扑；
- Candidate Coverage@15至少90%，干净表报警率不超过20%；
- MRR或Top-5至少一项稳定优于最强无真值基线，且不是单一族贡献；
- 至少完成一个真实错误语料验证；
- 有完整消融、失败案例和100—5000公式性能实验；
- 所有数字和图表能从原始CSV自动重建；
- 现场可对未见工作簿输出Top-5、修复建议和传播路径。

这些是内部目标，不是竞赛官方获奖保证。真正能支撑银奖竞争力的是：问题边界清楚、数据来源诚实、实验冻结严格、结果可复现，并且失败案例也能解释。
