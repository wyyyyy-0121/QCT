# V5.1.8-development 完整开发计划

状态：计划稿；尚未启动 V518 实现或实验。

## 1. 目标

在完整保留候选空间、完整定位排名、现有浮点求值及容差语义的前提下，
让一批 V517 因小数值回退而超预算的案例获得可验证的唯一联合修复。
先以完整穷举交叉验证，再评估 24/32 个候选格。

本轮研究问题是“能否可靠扩大小数输入上的搜索适用范围”。不预先承诺覆盖
任意浮点公式、任意依赖图或任意规模，也不将开发正例推广为真实业务安全结论。

## 2. 当前基线与边界

- V517 使用 V514 的 bounded edge proposals、原有 signature 去重，以及每格
  “不改”选项；搜索域为直接参与批准 aggregate 的候选格。完整候选档案照常输出。
- V4/V511 两个定位后端提供全部公式格、顺序、分数和定位证据，修复层不重排。
- V517 的优化要求 aggregate 成员不依赖其他候选变量，且贡献为整数值、最大
  绝对贡献总和不超过 `2**52`。不满足时回退到受预算限制的穷举。
- 现有通过条件来自 `_satisfaction`：按原求值器得到成员值，转为 float，
  调用 `math.fsum`，再以 `rel_tol=1e-10, abs_tol=1e-8` 调用 `math.isclose`。
- V517 的工程实验已包含 30 次较小空间穷举对照及 40 次大空间诊断；相关结果
  属于已知生成器家族上的工程证据。实施前按现有文件和测试重新核对基线。
- 制定本计划时，V517 源码、测试、报告和验证证据尚未提交、推送。

V518 不修改 V515/V516/V517 的源码、冻结回执、历史结果、默认定位后端或
受保护数据。不扩大候选生成范围，不同时解决跨候选依赖，不自动写回工作簿。
真实业务约束验证不作为本轮合成实验的完成条件。

## 3. 成功条件

下列条件必须全部满足，才能称本轮目标完成：

1. 数值界限有明确推导、适用前提和失败出口；不能仅凭测试未失败声称可靠。
2. 每个被剪枝的前缀都能证明其全部后继无法通过原 `_satisfaction`。
3. 小空间完整穷举与新版在唯一解、无解、多解分类及唯一接受公式上无不一致。
4. 同一输入、同一预算下，至少 12 个不同工程工作簿从 V517 的小数回退超预算
   变为 V518 的唯一修复，覆盖至少 3 类公式，每类至少 2 个实例。两个后端均
   验证，但不将同一工作簿计算成两个独立实例。
5. 候选域、候选档案、全部公式格、排名、定位分数和定位证据变化均为零。
6. 唯一接受证书可回放；未知求值、预算不足及多解不授权新联合动作。
7. 完成预定的 24/32 格评估，保存全部成功与失败案例；大空间通过证书回放
   验证，不冒称已进行全空间穷举。
8. 全仓测试、数值边界测试、证据篡改测试和 Ruff 通过；代码、协议、原输入、
   预测与报告均有可核对的版本和哈希。

“观察到零不安全接受”是本轮验收条件，不等于证明总体风险为零。
若某一条件未达到，保留实际结果并标记为未通过，不通过删案例降低门槛。

## 4. 数值设计

### 4.1 不改变被验证的语义

最终接受仍使用原工作簿求值器和 `_satisfaction`。既不把 `0.1` 当作数学上的
精确十分之一，也不假定所有金额都只有两位小数。不能通过乘以 100、取整、
改变容差或把原计算替换为 Decimal 计算来获得唯一解。

精确辅助表示优先使用标准库 `Fraction.from_float` 或 `float.as_integer_ratio`，
表示实际 binary64 输出对应的精确有理数。它们用于推导搜索界限，不重新定义
工作簿公式的业务或数值含义。不为此重新实现一套浮点求值器。

### 4.2 首先完成证明义务

需要明确区分：公式成员的实际 float 输出、这些 float 的精确实数和、
`math.fsum` 的实际输出，以及最终 `math.isclose` 判断。

数值设计文档必须回答：

- 为什么原公式与所有候选公式的引用并集足以排除候选间的传递影响？
- 如何从每格完整选项得到所有剩余组合的精确上下界？
- 在声明支持的 Python/平台数值环境中，如何包围 `math.fsum` 的实际结果，
  包括舍入、可能的中间误差、消去和异常？不能直接假设其始终正确舍入。
- 如何把误差包围转换为“所有实际结果均不可能被原 `math.isclose` 接受”？
- 端点比较是否包含容差边界，是否会把第二个容差内解排除？
- 上溢、非有限值、异常、无法建立界限或环境前提不满足时如何回退？

定向向外舍入可作为实现手段，但“随意多加几个 ULP”不构成误差推导。
平台自检和性质测试用于检查推导前提，不能代替推导本身。误差界限过宽时少剪枝，
不能为了覆盖率缩窄未经证明的界限。

### 4.3 运行路径

保留原整数精确路径；新增小数保守界限路径；其他情况保留完整候选域上的预算
搜索。首次实现继续复用 V517 的独立性条件，不按工作表或部门擅自拆分事务。

搜索预算约束工作量，不约束允许参与唯一性判断的原候选域。不得通过 Top-k、
限制修改格数或删除“不改”选项来降低证明难度。

## 5. 实施阶段与进入条件

### 阶段 0：保存 V517 基线

检查当前改动、V517 证据回放、测试和文件范围。将 V517 代码与对应材料作为
明确基线提交并推送，核对远端提交；V518 计划及后续实现分开记录。
保存算法文件哈希、Git 提交、Python 版本和数值环境信息。

交付：可复现的 V517 基线。此阶段不修改旧结果或合并其他分支。

### 阶段 1：数值协议与最小实验

建立只涉及成员输出、求和和容差的最小试验，写出第 4 节的推导和支持边界。
检查 Python 文档及所依赖实现的保证，固定需要验证的运行环境前提。

交付：`research/V518_NUMERIC_PROTOCOL.md`、最小数值试验及对应测试。
进入条件 G1：误差包围和排除规则可逐步检查，未解决的问题具有明确回退出口。
若 G1 未通过，不进入大规模唯一接受实验；可交付数值可行性负结果。

### 阶段 2：新增模型与证书

新增 `formulaguard/v5_1_8_development.py` 和必要的局部数值辅助模块；保持旧文件。
API 仅新增显式 V518 入口。复用已有 Diagnosis、候选域规则和前缀空间覆盖方式。

证书除原输入绑定和前缀覆盖外，记录数值规则版本、运行前提、贡献的可复核表示、
排除约束及界限证据。验证器从输入重建数值证据，不能信任预测内自报的区间。

必须区分“完整唯一证明”“两个有效解见证”“无解证明”“计算未知”“预算中断”。
找到一个解后中断仍不接受；找到两个有效解即可报告歧义，不声称精确解总数。

交付：V518 模型、API、数值证书及回放实现。
进入条件 G2：基本状态、输入绑定、整组原子性及候选/排名不变量测试通过。

### 阶段 3：小空间差分与失败注入

候选格梯度覆盖 2、4、8、9、10、12，并包含每格三个或更多选项的样例。
按实际选项乘积划分穷举范围，不以“格数较少”代替空间完整性。
本阶段声明的穷举案例空间不超过 65,536；较大案例另列，不能声称有穷举参照。

参照使用原求值器枚举全部原组合，统计 0、1、至少 2 个有效解。V516 可运行的
案例同时调用其穷举实现；检查新版唯一解公式与参照完全一致。

对每个被剪枝前缀，在这些可穷举样例中额外检查它包含的全部后继确实无有效解。
这比只检查最终接受公式更强，可以发现漏掉第二个解的错误。

覆盖数值类型：二进制可精确表示小数、不可精确表示小数、除法结果、负值、
正负消去、极小量、大数混小量、正负零，以及相对/绝对容差交界。
使用边界两侧和相邻可表示数构造案例；次正规数和极端量级至少验证正确回退。

覆盖业务/结构状态：合法例外、干净输入、错误抵消、多解、无解、数值碰撞、
原约束已满足、旧或候选新增传递依赖、无批准、过期或矛盾约束、缺失输入。
未知求值使用明确的失败注入测试，不算作自然业务样本。

篡改测试包括：删除/重复前缀、伪造数值界限、替换规则版本、变更文档或批准、
修改候选域、改变排名、删组成员、伪造完成标志及改写预算。

交付：差分结果、每个失败的可复现反例、完整测试集。
进入条件 G3：零错误剪枝、零唯一性不一致、零定位/候选变化。

### 阶段 4：超过 256 状态的正式工程里程碑

主工作量预算沿用 V517 默认值：`max_nodes=10000`、`max_evaluations=4096`、
`max_preparations=4096`；V518 不另行偷偷增加预算。记录新增数值准备和证书成本。

拟定正例矩阵为 3 类小数公式、2 类约束结构、4 个预定实例种子，共 24 个
不同工作簿；每例目标 13 个二元候选格，即 8,192 个原组合。三类公式优先为
费率乘法、除法分摊和加权金额；约束包括全域总额与混合方向错误加固定分组小计。
具体模板和种子在本阶段开始前锁定，不按运行结果挑选。

比较 V517 与 V518 的相同预算结果；另为穷举参照配置足够预算，必须明确标为
参照实验，不能将其当作相同预算对比。没有进入预期候选域的实例也保留并记失败。

进入条件 G4：达到第 3 节至少 12 个实例的改进门槛，两个后端都通过，所有
新增唯一接受均经穷举和证书回放。24 个实例完整报告，不仅报告其中成功者。

### 阶段 5：开发期规模与消融

G4 通过后，依次测试 16、24、32 格。采用相同输入和固定预算比较：

| 模式 | 用途 |
| --- | --- |
| V517 默认 | 现有能力基线 |
| V518 完整 | 新小数界限的主结果 |
| V518 关闭小数界限 | 隔离新增数值机制的贡献 |
| V518 低预算 | 检查中断与唯一性边界 |
| V518 review_only | 检查零自动接受时排名与候选不变 |
| V518 reject_all | 检查拒绝策略及完整输出 |

每种模式运行 V4/V511；不跨后端混比分数。小空间另有 V516 高预算穷举参照。
计时采用串行基准，固定环境并记录重复运行的中位数、尾部耗时和最大值；
重复诊断不作为额外样本，定位时间与修复时间分开记录。

进入条件 G5：全部预定规模和困难场景完成测量，无不安全接受或不变量回归。
不要求所有 32 格案例可解，但不得只挑有利结构宣称普遍扩展。

### 阶段 6：冻结后确认

先完成开发与消融，再冻结算法、依赖、数值规则、测试、生成器、评分器、运行
预算和协议。确认种子在冻结后产生；生成输入和标签分开存储，推理只读取输入。
锁定全部模式的预测、人口清单与哈希后才运行有权限读取标签的评分步骤。

拟定确认矩阵：3 类公式 × 12 类情形 × 2 个规模（24/32）× 2 个实例种子，
共 144 个工作簿；6 个模式、2 个后端，共 1,728 次诊断。
12 类情形为：唯一修复、混合方向加小计、多解、错误抵消、无解、干净、合法
例外、数值碰撞、容差边界、无效批准、跨候选依赖、弱界限预算压力。
失败注入仍属单元测试，不冒充确认集的自然样本。

该矩阵是当前资源计划；开发试运行可在冻结前通过有记录的协议修订调整规模。
冻结后不得改样本数、重抽失败种子、增加约束或上调预算以通过确认。
评分器从冻结协议重建预期清单，不能只验证结果文件自报的人口数量。

此流程减少开发后调参，但同一已知生成器的新种子仍不是第三方独立盲测。
确认若出现不安全接受、排名变化、错误数值证明或证据不完整，本轮确认失败。

### 阶段 7：审计、报告和交付

从原输入、预测和标签重新核对整组正确性、唯一性证书、完整分母和排名；
再次验证源码与数据锁。运行最终全仓 pytest 和 Ruff，并保存执行日志。

报告同时给出成功、歧义、无解、原约束已满足、数值不支持、依赖回退、求值
未知和预算中断。记录适用路径比例，不把零动作模式解释为更强的修复能力。

按文件清单提交并推送 V518 源码、测试、协议和应版本化证据，核对远端提交。
大型生成材料遵循项目现有 results/ 所有权及忽略规则，不强制上传未跟踪原始数据。

## 6. 指标与报告口径

| 指标 | 要求 |
| --- | --- |
| 完整定位 | 全部格、顺序、float 精确表示、定位证据变化为零 |
| 候选空间 | 完整选项档案和原乘积不变；不得丢“不改”选项 |
| 唯一性 | 小空间参照一致；接受证书完整覆盖且可回放 |
| 修复覆盖 | 正确修复格/全部应修复格，失败与超预算不删分母 |
| 事务正确性 | 整组全部正确才计正确组；单独报告不安全接受组 |
| 适用比例 | 整数优化、小数优化、各类回退分别统计 |
| 成本 | 准备求值、节点、叶求值、覆盖空间、证书大小、内存、回放耗时 |
| 总耗时 | 定位、候选准备、搜索、验证及端到端分别统计 |
| 对照公平性 | 相同输入、批准上下文、候选域及预算；额外参照单列 |

后端复用、生成器家族和同模板实例存在相关性。报告原始工作簿数与诊断次数，
不得用重复后端或重复运行扩大独立样本数；零失败不推出总体零风险。

## 8. 失败处理与执行顺序

误差界限无法证明：停在 G1，保存反例及未解决前提，不发布小数唯一接受机制。
界限可靠但过宽：保留回退，报告覆盖/成本未改善；不缩减候选域换取通过。
穷举发现漏解：阻止 G3/G4，修复并重跑受影响的差分和边界测试。
确认失败：保留原确认结果；任何后续修改作为新版本或新实验，不覆盖旧记录。
证书或冻结源变化：评分前失败，恢复匹配的实验上下文或重新开始有记录的新实验。

执行顺序固定为：保存 V517 → 数值证明 G1 → 实现 G2 → 差分 G3 → 小数
超预算里程碑 G4 → 规模与消融 G5 → 冻结确认 → 最终审计、提交、推送。
数值证明是主要不确定项；不在 G1 之前承诺完成日期或生产可用性。
