# FormulaGuard core-reset-b Phase 0 数据审计结果

日期：2026-08-31
状态：Gate 0 通过；只授权进入 Phase 1 文献与真实基线门

## 1. 证据边界

审计器 `scripts/audit_core_reset_b_data.py` 在提交
`5be35ee9d78b93d9d5880db15259897a099adcd0` 上读取三类永久揭晓开发数据：

- 公开压力 60 错误 + 30 控制；
- 历史独立 100 错误；
- Enron 30 事件。

审计不运行任何排序器，不读取源格来生成预测，也不读取旧 `240+120` revealed-trial
或新保管人最终盲测数据。输入清单共记录 308 个 manifest/workbook 文件及 SHA-256。

## 2. 分组结果

| 队列 | 事件 | 来源组 | 结构外层组 | 处理规则 |
| --- | ---: | ---: | ---: | --- |
| 公开 60+30 | 90 | 22 | 17 | 原始工作簿哈希，再合并完全相同结构模板 |
| 历史 100 | 100 | 100 | 95 | 工作簿哈希，再合并固定阈值近重复 |
| Enron | 30 | 25 | 25 | 工作簿哈希；同工作簿事件同组 |
| 合计 | 220 | 147 | 137 | 外层折使用结构组，不使用事件随机拆分 |

公开控制的 11 个原始工作簿组全部也是错误队列 22 个来源组的子集。它们不是额外
11 个独立模板。错误版本、对应原表和控制必须留在同一外层折；把它们拆开会产生
成对模板泄漏。

## 3. 结构重合

固定近重复阈值为：公式数比例至少 0.90、公式指纹多重集 Jaccard 至少 0.90、
平移归一布局 Jaccard 至少 0.85、依赖度直方图 Jaccard 至少 0.85，并要求工作表数
相同。

历史 100 中识别出 5 对近重复：

- `independent_020` 与 `independent_074`；
- `independent_024` 与 `independent_078`；
- `independent_032` 与 `independent_086`；
- `independent_040` 与 `independent_073`；
- `independent_041` 与 `independent_095`。

公开 Modified EUSES 中另有 5 对不同内容哈希但公式、布局和图摘要完全相同的来源
模板组。完整实例成员保存在本地 `structural_overlap.csv`，后续评分使用合并后的
`structure_cluster_id`。

三类主要队列之间没有内容完全相同或达到固定阈值的结构重合。leave-one-corpus-out
仍固定排除与留出队列共享结构组的训练成员，以防未来数据增加后产生重合。

## 4. Gate 0

以下检查全部通过：

- 90/100/30 事件数量和 60/30 case-kind 数量正确；
- 公开 22/11 来源组、Enron 25 工作簿组可复算；
- 共享错误/控制来源保持同一外层组；
- 220 个事件都有来源组、结构组和外层组；
- 147 个来源单元全部完成工作簿结构指纹；
- 跨队列内容哈希无重合；
- 评分分组导出不含 `source_cells`、`case_kind`、错误类型或正确公式；
- 禁止的 revealed-trial 和最终盲测输入读取列表为空；
- 第二次独立输出目录重跑与首次五个产物逐字节相同。

因此 `gate_0_passed=true`。这只证明分组与数据用途边界可执行，不证明任何新模型
有效，也不允许读取两套 `240+120`。

## 6. 限制与下一步

历史 100 没有出题人提供的模板 ID 或原始正确工作簿。固定结构聚类能识别强近重复，
但不能证明剩余 95 个结构组没有共同生成祖先。因此历史 100 继续只作揭晓开发证据，
不能恢复为独立验证。

下一步是 Phase 1：为原文方法建立可比输入/输出/指标卡，核实原实现可运行性，并将
“超过 V4”与“超过公开原工具”分成两条证据链。Phase 1 完成前不实现候选主模型。
