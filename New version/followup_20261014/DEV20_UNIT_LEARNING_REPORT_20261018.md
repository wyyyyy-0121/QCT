# dev20：可见单位阻止成本相乘误修，修复覆盖仍是瓶颈

本轮继续开发论文原模型的后续研究，新增可见单位特征和量纲拒绝门。原论文0.3.0、dev11主候选和旧锁均保持不变。资料检索已有六个大学计算表目录和具体下载入口，但自然错误原表/可靠修订配对、6个合格新来源/15模板家族及三类最终双90%仍未完成。

## 已锁定dev19的单位门对照

不重训dev19，只对其87条冻结建议应用单位门：80条UK相乘误修全部拒绝，Iowa的3条和Packt的4条已确认正确修复全部保留。冻结标签评分为87建议/7正确/80未知 → 7建议/7正确/0未知；确认精确率下界8.05%→100%，已标错误修复覆盖保持7/18,073=0.0387%。80条的旧标签仍保持unknown，后验已确认为误修；未改标签或重新定义分母。7条样本不支持普遍100%的结论。

独立openpyxl直接读取工作簿，确认被拒绝80条是5个原始单元格在16副本的重复，每条均将同列两项相加改为相乘。输入与输出的£m单位、行和单位列/输出列均可见；未依赖隐藏说明列。这里验证的是局部形式量纲，不认证上游财务业务或数值结果。不能把80重复建议写成80个独立错误家族。

## 新特征与实验设计

复用unit_evidence_dev1有界AST量纲检查，仅从可见文字提取单位。最近的可见列文字末尾[unit]最多向上8行；目标同一行左侧16列内的独立单位文本限定白名单。£m、£、£'000s等保留书写尺度，不推断换算，冲突、缺证据和不支持语法保留unknown。

原式和候选各有compatible/incompatible/unknown三状态及其差值，共9个特征；追加到dev19的347维，共356维。只有状态进入学习器，不把单位名、单元格坐标或文字放入新增向量。单位一致不能确定加减号、系数或业务意图。

候选池、213输入、1,861,162候选顺序、旧标签、五个整来源折、权重、100轮模型参数和0.90/0.05选择规则不变。单位门在选择与差距规则之后拒绝明确incompatible建议，不删除竞争者制造差距，不提升备用候选。另存learned_unfiltered以区分训练变化与门的作用。unknown继续允许原阈值选择，绝不标记为兼容。合并模式保留dev11，实验未替换主候选。

无标签特征检查：只有32,692/1,861,162（1.7565%）候选获得可判定单位状态；其余98.2435%为unknown。Iowa、18F和Packt所有候选均缺可判定单位，本轮不能声称为这些来源获得了语义证明。新增单位也不能解决方向或同量纲系数错误。
