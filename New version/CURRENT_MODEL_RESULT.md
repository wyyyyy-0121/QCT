## 1. 实验是否完整

当前开发集按固定生成器运行了 51 个工作簿、两个定位后端和六种模式，共 612 次诊断。冻结的 454 个源码文件、612 个预测分片和历史指标均通过哈希或逐项核对；282 个 `unique_solution` 证书重放通过，聚焦测试通过。评分门控为 `gate_passed=true`。

模型工作阶段约 692.73 秒。预测阶段不读取错误标签，`prediction_lock.json` 的 `labels_read` 为空。结果属于已经揭示的合成开发集，不能当作独立真实业务验证。

## 2. 开发集总结果

每个后端看到同一批 4,872 个公式单元格，其中 735 个为生成器标注错误，4,137 个为正确公式。51 份工作簿全部含错误，因此没有独立的全干净控制组。

输入来自 product、ratio、weighted 三个已知生成器家族。六种模式重复诊断这些输入，612 次诊断不能写成 612 个独立工作簿。定位指标按工作簿取宏平均；ordered AP 使用 API 的确定排序，同分不重新合并。

“候选误建议”是模型给出的候选组合中落在正确公式格上的错误候选，不等于已经写回工作簿的修改次数。“最终接受精确率”只适用于这批有完整生成器真值的开发集；它不能推广为真实工作簿安全保证。

精确匹配采用评分器的公式规范化规则。本轮每个提供修改的单元格恰有一个去重后的不同公式候选，因此候选对数与候选格数相同。正确公式格上的候选误建议率分别为 3,408/4,137 = 82.38% 和 27/4,137 = 0.65%；V5.1.1 的 27 个全部出现在三份 `coupled_ambiguous` 输入中，最终没有接受。

V5.1.1 在开发集上大幅减少了错误候选，V4 和 V5.1.1 的最终接受覆盖相同。这个结果支持把候选生成与最终接受分开评价，也说明后续需要在外部数据上保留两个后端作对照，不能只凭合成集选择 V5.1.1。

## 4. Enron 回顾性回归

本次使用已有、公开且此前已经揭示的 Enron 清单，固定 180 秒/工作簿/后端超时，25 个唯一工作簿、两个后端共 50 个任务。原始 36 个事件中预纳入 30 个，预排除 6 个；超时按未命中处理。这个实验没有完整正确公式，因此不能计算修复精确率，也不能计算工作簿级误报率。

50 个任务全部尝试并记录，45 个成功、5 个超时。`RESULT.json` 中 `all_tasks_completed=false` 表示预测没有全部成功，不表示任务清单漏跑。本轮不重试超时；更大的预算应作为新实验单独保存。TopK 表示“一个事件的任一已标注源格出现在前 K 个位置”，不是逐错误格召回率。

预排除沿用已有清单：事件 17 为 Label 类型，18 和 20 为 Value 类型，21 缺失故障工作簿，27 的 overview 与 properties 工作表标签冲突，31 的插入位置没有公式。这些案例和原因都保留在 `ORIGINAL_MANIFEST.csv`。

没有外部批准业务约束，所有成功输入的搜索状态都是 `no_approved_constraints`。结构策略仍保留了 8 个旧逻辑的 `accepted` 决策，两个后端各自相同：`03.xlsx` 的 3 个单元格、`21.xlsx` 的 1 个单元格和 `25.xlsx` 的 4 个单元格，理由均为 `stable_copy_template`。这些决策的正确性未知，后续需要单独门控，不能把它们计入真实修复精确率。

具体位置为 `03.xlsx/BMSPT066!H40,I40,J40`、`21.xlsx/Sheet1 (2)!E127`、`25.xlsx/external!E36,F36,E37,F37`。完整候选公式和决策见 [推导审计](20261014_reports/DERIVED_RESULT_AUDIT.json)。成功任务均确认模型内存中的原公式没有变化，输入文件和预测哈希已核验。

## 5. 当前结论

当前模型在已知合成开发集上可以提供较高的接受覆盖，V5.1.1 的候选组合明显更干净；在 Enron 回顾性定位上，V4 的 Top10 略高且更慢，V5.1.1 更快但 Top10 略低。当前证据足以决定评价协议和数据适配顺序，尚不足以决定最终后端或声称真实业务安全。
