# M2：候选池缺口已经定位

本轮没有改模型规则。20-worker批次完成全部100项输入类型库存，其中90项重跑paper并记录实际候选；这些90项的paper输出及原公式库存均与冻结结果内容完全一致。另10项仅做XML库存，原900秒超时状态不变，没有重新推理。实际记录774,810条按单元格去重的阶段候选，包含35,700个FormulaGuard触发格和117,921次StructuralGuard候选调用。

## 普通公式候选分解

以下仍是已有10,948个golden普通公式差异候选，不是认证错误标签。

| 互斥情况 | 格数 |
|---|---:|
| 最终建议精确 | 449 |
| 实际观测候选池有精确式，但未最终选中 | 225 |
| 目标在原公式库存中，但观测池无精确式 | 2,475 |
| 目标不在原公式库存中 | 2,406 |
| 原基线超时，候选池未观测 | 5,393 |

观测池并集可达674格：FG可达247、SG可达533，两者重合106。即使对当前已观测池使用知道答案的理想选择器，也只能覆盖全部候选分母的6.1564%；这不是可实现的模型得分。90项已完成任务中普通候选共5,555格，原公式库存内3,149格；观测池对后者可达21.4036%。对超时项未观测的池不作上限断言。

225个未选中的精确池候选中，124格仅有FG精确候选但未发出；89格SG已发出精确式却被融合覆盖；2格SG选中后被门槛拦截；10格兼有FG未发出和SG被融合覆盖。该分解支持后续分别研究候选生成、触发、选择和融合，不能笼统归结为同一阈值问题。

2,475个无精确池候选的格中，1,806格没有触发FG探查，669格触发后仍无精确式。FG池只覆盖触发后、原24候选上限之后的实际探查，不代表截断前所有潜在候选。SG池记录实际翻译且通过原安全检查的式子；范围内不存在精确式不证明任何其他机制都不可能生成。

## 接口和差异表示

2,406个不在原公式库存中的目标，原XML类型分别为：40个dataTable公式声明、689个文本、251个数值、288个错误值、718个空白单元格和420个缺失单元格。不能统称常量错误；其中可能包含删除行/结构变化造成的地址失配，逐格业务真值仍须独立认证。原模型只输出其公式库存中的格，这一接口缺口无法靠排序弥补。

旧审计189,151处golden数组对象差异中，189,037处的数组类型、公式文本和数值范围边界相同，仅有单格范围写法差异；它们在现有差异表示中归为表示一致，不能算漏修。102处普通公式转数组而文本相同，仍因类型语义未知保留；11处转数组文本改变/缺失，以及1处数组文本改变也维持未知。另有3处数组转普通公式文本改变/缺失，已位于旧普通公式候选中，但仍未认证。2,466处公式删除差异独立保留。本轮不回写旧预测或将表示一致计作模型修复成功。

## 结论与下一实验

当前未证明修复能力提高。仅调整当前排序/融合不足以解决已完成任务中的主要候选缺口；同时，任何通过删掉超时或非公式目标来抬高覆盖率的做法均不允许。

原FG同伴生成与SG候选翻译主要沿列执行，财务表中横向期间复制可能缺失。下一实验只增加横向同伴候选，沿用原解析/翻译器、半径5和支持数2；测试候选可达增量及候选规模，不自动选择候选，不声称取得修复准确率。M1合法业务例外反例仍有效，复制一致性只作候选来源。

观察器返回身份/异常恢复和XML类型测试3项、独立评分分类测试4项通过。该批墙钟39.022秒、CPU合计614.00秒、采样聚合RSS峰值约3.16GiB，是包含追踪的paper与库存混合任务资源记录，不与旧含dev11入口作速度对比。逐格追踪、输入和差异留在本地忽略目录，GitHub仅保存聚合结果和工具。没有改变自然最终验证0来源/0模板家族的现状。
