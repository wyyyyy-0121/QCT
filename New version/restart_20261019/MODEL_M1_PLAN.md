# M1：双侧复制一致性筛选实验

## 范围和假设（运行前固定）

停止并发档位测试。后续模型批处理固定请求20 workers，保留正常资源记录；原论文模型、冻结入口及100项预测锁不改。

本轮研究原模型的建议筛选层，不更换为旧QCT修复路线。SpreadsheetBench 2全部已揭示，只作开发诊断，不能把其中任何分组重新称为盲测。golden公式差异未经业务认证，所有结果都称候选差异指标。

假设：相邻复制区域中，目标格两侧的公式各自平移到目标后，若得到同一条公式，且与原模型建议完全一致，可以减少无支持的修改建议。该证据不是业务正确性证明；合法的单格业务例外也可能满足条件，必须保留此反例测试和限制。

## 固定方法

只读冻结预测中的原始公式和paper行，不读取工作簿、任务说明、golden或标签。分别检查同一行左右紧邻一格、同一列上下紧邻一格；至少一个方向两侧均为可平移的简单A1公式，且平移结果逐字一致。若两个方向均有一致结果却互相冲突，拒绝。仅当结果等于paper现有建议且不等于原式时保留，其他建议置为空并记录拒绝原因。命名范围、结构化引用、外部引用、3D引用和非普通公式均拒绝。不得通过标签选择窗口、阈值或规则。

冻结90项已完成预测各形成一个独立后处理任务；10项超时不补成成功、不移出分母。执行使用20 workers，不重新跑原模型或性能比较。全部M1输出生成并锁定哈希后，独立评分器才读取已有候选差异。

## 可否证标准

本轮只运行这一组规则。继续研究此筛选方向的必要条件为：全部建议减少至少90%，保留原449条精确候选中的至少90%，且候选精确率至少为原值10倍。无论是否通过，均报告总分母下的正确修复覆盖率、候选来源/状态、错误类型以及超时。必要条件通过也不构成正式采纳或90%达标。

若不通过，不在本数据上搜索更多阈值或窗口。转向候选生成缺失、候选选择缺失和信息不足的机制实验；已有paper单条建议的筛选覆盖上限只是449/10948，不代表模型所有潜在候选的上限。选择错误与候选池缺失不能只根据当前最终建议区分，必须标为未决。

## 实现验证

运行有实际意义的模型逻辑测试：双向一致、边界冲突、未变公式、复杂引用拒绝、原输出不被改写、以及合法单格例外的失败案例。评分复用独立精确公式口径。保留代码哈希、冻结输入/输出哈希、20-worker运行日志。第三方公式和逐格结果只存忽略目录，GitHub只提交工具和汇总。
