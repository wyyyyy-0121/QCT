# M3：横向候选扩展未通过继续条件

20-worker批处理完成90/90个原基线成功任务。半径5、支持数2固定；只增加由论文原生解析/平移器产生的横向候选，没有改原模型、排序或阈值，没有生成被选择的修复建议。全部候选锁定之后才读取旧差异评分，原10项超时和对应5,393个普通目标继续保留在10,948个总分母中。

新增候选/新增精确目标为445.91。预设“至少新增100个精确目标”和“每新增精确目标至多100条新候选”均失败。因此停止这个独立机制，不据此搜索其他窗口或支持数，不进入修复选择层。合法单格业务例外测试也显示横向复制可为正确公式生成错误候选，不能把生成支持当作业务认证。

合并候选池在全分母下的理想可达覆盖由6.1564%变为6.5765%，增加0.4202个百分点；这是假设知道答案后选择的候选上界，不是模型修复覆盖率，更不是准确率提升。既有最终449条精确候选输出未改变。对原10项超时的池仍未观测，不将此可达率外推为整个模型内部完整候选空间的上限。

新增可达46个目标来自7个已揭示模板目录，其余2个完成目录无新增；第10目录只做过类型库存。四项生成器测试通过，覆盖绝对/跨表引用、支持数、直接/范围自引用和合法业务例外不自动修改。原解析器不支持的原式共有4,911个按任务计数的公式格，保持不支持，未通过换解析器或过滤分母处理。

本批是轻量候选生成，不是完整原模型重跑：墙钟1.302秒、子进程CPU合计19.89秒、采样聚合RSS峰值约532MiB。不做并发对比。详细候选与源公式仅保存于忽略的本地证据，公开汇总为`MODEL_M3_HORIZONTAL_SUMMARY.json`。

下一步按M2已经确认的缺口开展输入/解析能力研究：先核对缺失公式和不支持AST类型的真实组成，区分结构变化引起的地址不对应；同时保留显式业务约束路线。不得将未认证golden差异作为真实错误，把现有开发集反复调优结果当成独立90%结论。
