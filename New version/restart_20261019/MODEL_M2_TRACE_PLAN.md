# M2：原论文候选池与输入类型诊断

本轮为机制诊断，不修改修复规则、阈值或候选排序。沿用论文交接包和冻结100项输入，数据已揭示，只作开发。M1筛选路线已否决，不尝试更多筛选参数。

## 执行前固定

1. 对90项原本完成的任务，以20 workers重新执行原论文paper路径，记录FormulaGuard实际探查的候选及分数分量、StructuralGuard实际生成并通过安全检查的同伴候选及预门槛选择。记录只读观察包装器，不改冻结源码或函数返回值。输入、实现、原预测及新输出均校验哈希；新paper输出必须与冻结paper内容相同，否则保留差异并停止汇总候选结论。
2. FormulaGuard记录的是触发条件成立后、24候选上限之后实际探查的池，不冒称截断前完整生成池。StructuralGuard记录原实现实际翻译且安全检查通过的池；未通过安全检查另计。候选池包含精确目标仍不代表能唯一识别正确答案。
3. 原10项超时只做输入XML类型库存，不再重复900秒推理；它们继续留在总体候选分母，模型候选状态记为未观测。不得从90项推断这些任务的候选表现。
4. 每项只读取对应原工作簿及必要代码/冻结输出，不读取golden、任务JSON或差异标签。运行全部终态锁定后，独立诊断器才能读取已有差异。
5. 输入XML库存区分普通/数组/共享公式、数值/文本/布尔/错误/空白及缺失。独立差异审计只将文本完全相同、数组类型相同且范围数值边界相同的数组变化归为“表示一致”；普通与数组类型转换、文本改变、区域改变维持未知，不用文本相同推断业务等价。

## 报告和判断

对既有10,948个普通公式目标互斥分类：最终建议精确、最终未精确但实际候选池包含精确式、目标属于原输入公式但实际观测池无精确式、目标不在原公式库存、原基线超时。候选池包含而最终未选须细分FG、SG、融合覆盖关系；追踪未完成另计，不排除分母。

单独报告原始差异表示审计、2,406个非公式库存目标的XML类型、候选池覆盖、最终覆盖和不支持情况。数组公式仍不进入旧普通公式指标；表示一致计数不当作“修复正确”。若候选池新增可达率不足以支持90%，明确否决仅改排序即可达到90%的假设，依据主要缺口再登记一个生成或输入机制实验。

验证包括观察包装器返回值和恢复保证、实际候选池而非虚构候选、数组范围规范化、非公式/共享公式输入分类。全部逐格数据仅存忽略目录；GitHub保存工具、计划、汇总和失败记录。资源只记录本批模型执行，不开展并发档位测试。
