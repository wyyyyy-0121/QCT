# M6：从显式业务关系补充原论文候选

在M1/M3/M5未取得修复性能增益后，本轮单因素为“从显式关系生成缺失候选”，沿已有E3验证器扩展。原论文源码、原候选规则和阈值不改。新输入是用户/专家提供的有单位的符号到单元格映射与关系，不是人工候选公式；不提供修正工作簿，不从评分标签抽取关系。EPA D36沿既有表内定义/官方勘误证据，仍为已经揭示的开发案例。工程反事实不计自然样本。

## 固定算法

对每个明确指定的审查目标，先运行paper并观察其候选池。关系为受限有理算术的lhs/rhs，输出符号y；输入符号为正数域，单位显式声明。仅解对y为一次且系数在声明域内可证明非零的关系；非线性、不确定唯一性、矛盾关系、单位不符、映射缺失/多义和不支持语法均拒绝或标不支持。根据唯一关系解及引用映射构造新公式，附加到原池，再由E3符号验证器检查原式及候选。原式满足关系时不建议改动。

IF案例只替换明确指定的活跃分支，原guard与非活跃分支的原始字节前缀不变。保证的是给定业务约束及正数域下活跃分支等价；不证明guard本身、所有上游公式或真实输入均符合域。未提供约束的其余paper建议继续为未认证建议，不把它们悄悄计为“通过验证”。本轮不扩展到空白/常量目标或Excel一般语法。

## 固定条件与核验

EPA条件：无关系、有效稀释关系、冲突关系、错误IF分支声明。微型同字节工作簿条件：比例、仿射、无关系、仅单位、冲突、映射缺失、非线性、单位不符、域内唯一性不明、未声明符号。另以不同工作簿提供原公式已正确及合法业务例外。共16个条件，不增加条件数来包装准确率。

先固定实现、请求和独立预期，再用20 workers运行16个审查任务；并发上限由任务数16决定，不声称占满20核。全部终态与输出哈希锁定后独立评分。不能把16项工程验收称16个独立来源，不能称自然准确率达90%。

独立评分器不用SymPy或生成器，使用单独的受限AST/Fraction求值，在d=1以及多个可区分关系的有理点核对原式/新增候选；EPA另用Calc在受控输入副本上核对IF两分支，保留原工作簿。先确认生成目标不在原观测池，再报告生成增益；如原池已有等价式就不称候选缺失得到修复。

任何错误建议、缺关系仍建议、冲突仍建议、原式已正确仍建议、分支前缀被改写、输入变动或读取评分证据均触发停止接入。即使全部通过，也只证明显式关系驱动生成这一受限机制，自动业务关系抽取、完整工作簿精确率/覆盖、独立自然来源及总体90%目标均仍待完成。
