# M8结果：去掉人工地址表后，端到端修复0/2，停止标签规则路线

本轮将M7的人工references表移除，用静态标签、完整工况描述和单位生成地址。18项固定条件全部执行完成，诊断状态与事前预期一致，但**修复机制继续门槛未通过**。两个故意改错的M7副本均因映射不完整而拒绝，正确修复0/2；两个正确原件也未修改。没有模型准确率提升，不能把诊断通过报告成修复通过。

## 直接证据

| 条件组 | 数量 | 结果 |
| --- | ---: | --- |
| 原表字段查询 | 8 | 4个唯一结构地址，4个未决 |
| 人工静态单位控制 | 3 | 2个单位区分成功，1个单位冲突拒绝 |
| 人工布局控制 | 2 | 重复标签和值格移位均拒绝 |
| 仅改目标公式的不变性 | 1 | 地址候选与原件一致 |
| 端到端正确原件 | 2 | 均拒绝，不改原式 |
| 端到端公式故障副本 | 2 | 均拒绝，0个正确修复 |

合计7个mapped、7个unresolved、4个abstain；共0条修复建议。mapped只表示在声明布局下找到唯一结构地址，不表示业务角色已认证。8个原表查询来自同一已揭示EPA工作簿，不是8个自然错误或独立来源。

`Qwi`在原Data Inputs里对应两个字段：B23是标准工况，B24是实际工况。只提供符号时不能选；提供完整工况描述时可在该布局下定位。两个单位格本身是公式，快照不使用缓存来认证单位，故单加scfm要求仍不接受。只有人工副本把单位改为明确静态文本后，才能按scfm/acfm区分；这不能计为原件表现。`Tfi`同时出现在输入与设计输出位置，跨表查询也保持多义。

M7两处来源算式的浓度字段名称没有对应的完整静态行标签，去掉人工引用表后无法映射。更需警惕：`LELmix`可唯一匹配原混合气的D31，但M7稀释后条件用的是另一表区的S28。即使词面唯一，也不代表适用于稀释后业务角色；本轮由另一个浓度字段未决阻止了生成，不能将其误说成已经解决全部语义歧义。这正是不能继续靠添加同义词调通旧案例的原因。

## 隔离与核验

映射输入是仅含表名/地址/类型/静态文字的快照，不包含公式正文、数字值或公式缓存。推理入口只在前置阶段读取工作簿字节以核对哈希；map模式下审计钩子禁止进一步打开任何工作簿，映射函数只接收快照。修复模式也须先完成全部映射，之后才允许原论文推理读取公式。本轮4个端到端条件均在映射阶段停止，未运行paper候选生成。

原表及两个人工公式故障副本的完整元数据快照哈希相同，对应字段映射不变。独立评分器不导入映射器/快照生成器，用OOXML逐一核对6份工作簿的公式地址库存，并验证所有公式槽不含正文、数值槽不含值。原件与历史M7锁不变。5项机制测试通过，包括单位/科学符号大小写、未知单位不得被过滤、多值列歧义及公式/数值扰动不变性。

因没有修复建议，本轮独立Fraction核验数为0，没有Calc重算，也不借用历史控制声称当前端到端通过。查询词、所需单位、表范围和关系符号仍人工指定；同一代理实现并登记预期，没有独立人工标注。

请求并实际配置20 workers，只有18项任务，实际并发上限18。墙钟约0.247秒、子进程CPU合计2.85秒、采样RSS峰值约745MiB，仅记录本批运行，不做性能比较。

## 决策

停止标签匹配作为自动修复机制，不接入默认模型，不在当前样本上追加同义词、扩大窗口或调匹配分数。保留为发现缺信息和多义字段的诊断工具。原论文预测仍为当前基线，没有证明自然性能提升，90%目标及最终验证0来源/0家族均保持未完成。

后续需要的是可验证的字段角色、工况和业务前提，缺项登记见`MODEL_INPUT_EVIDENCE_GAPS.md`。下一机制必须同时审查“引用地址是否对”和“这条业务关系是否适用”，不得靠词面唯一或符号等价替代后一项。原文、快照、逐项结果和锁保存在忽略目录`source_evidence/raw/spreadsheetbench2/model_m8_mapping/`。
