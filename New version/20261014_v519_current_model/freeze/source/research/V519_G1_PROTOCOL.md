# V519 G1 组件表实验协议

日期：2026-09-07。范围：实现开发计划 G1，不开放 V519 修复接受入口。
本协议在正式矩阵运行前登记；旧 V518 模型、API 和历史证据保持不变。

## 固定实验

3 个 family：product、ratio、weighted。
4 个 structure：pair、chain、fan_in、shared_bridge。
3 个候选规模：4、8、12。2 个 seed：v519-g1-0、v519-g1-1。
共 72 个不同工作簿，不抽样、不按结果重选。每个工作簿须由原 V517 `_domain`
得到预定数量的二元候选，包含原“不改”选项；生成偏差即记录失败。
全部原始状态总计 `24*(16+256+4096) = 104832`。

每个样例保留 6 行局部公式，首行一个候选。真实依赖由首行 B 输入通过
`base + 0.125*upstream_H` 引入；chain 使用两级该计算；fan_in 使用两个上游；
shared_bridge 由一个跨表非候选公式相加两个上游，并影响两个下游，且该中间格
本身加入总额成员。约束包含全体成员总额和前两个部门小计。
生成器按健康公式的直接业务计算生成总额，不导入求解器或从预测反推批准总额。

## 核验步骤

1. 构建原/候选引用并集、每个成员的候选支持集和无向组件，保存每个局部赋值
   的原选项索引和逐成员 float 值。对缺失、超范围、循环和实际未知求值拒绝准备。
2. 确认存在真实耦合：用原求值器改变首个候选，观察另一个候选的 float 值改变，
   保存两个完整赋值与前后数值；此检查不读正确公式标签。
3. 独立按原候选域笛卡尔积穷举全部全局赋值。检查组件选择往返映射为双射，
   表重组后所有成员 float.hex 与原求值器逐项完全一致。
4. 使用原成员顺序执行 fsum/isclose，与原 `_satisfaction` 每条约束逐项比较。
   记录全部满足赋值，不将同值但公式不同的赋值合并。
5. 对每个全局赋值的全部组件前缀，检验该赋值实际 fsum 落在保守区间内，
   任何满足约束的后继不得被排除。前缀区间可缓存，后继比较不可省略。
6. 最后对照生成器正确公式，确认健康赋值存在于原候选域并满足全部约束。
   本轮不把已知标签称为盲测，也不把原型的穷举解集合当作可交付唯一性证书。

原型与定位后端无关；72 个样例各穷举一次，不重复两个后端来扩大样本数。
排名/候选兼容性由两个后端的小规模回归另行检查；全量后端对照留待新入口开发。

## 数值依据

静态引用并集覆盖全部原/候选选择。对任一 aggregate 成员，其所有候选先祖
被归入同一组件。因此在无环、固定非候选输入且使用当前确定性求值器的前提下，
该成员的实际 float 输出仅依赖该组件的赋值；无候选先祖的成员固定。
局部表完整枚举各组件赋值，不丢行，原域与组件选择域由索引重排构成双射。

令 `x_m(a_g)` 为成员 m 在组件 g 的局部赋值 a_g 下实际 float 的精确有理数值。
每条约束的组贡献为 `q_g(a_g)=sum_m x_m(a_g)`，此处为 Fraction 精确求和。
固定贡献 c 同样来自实际 float，前缀固定后剩余总和落在：

```text
L = c + sum(fixed q_g) + sum(min over all local assignments q_g)
U = c + sum(fixed q_g) + sum(max over all local assignments q_g)
M = sum(abs(fixed member values))
    + sum_g max over local assignments sum_m abs(x_m(a_g))
```

绝对规模使用逐成员绝对值和，不能用抵消后的 abs(q_g)；成员数使用原 aggregate
成员数，不能用组件数。继续遵守 V518 的 4096 成员和 `2**500` 规模上限及
已核对的 CPython/math 二进制环境。对 L/U 向外转换后沿用 V518 fsum 输出
包围与 isclose 舍入容差排除规则；原函数源码及假设见 V518 数值协议。
不通过先对组内 fsum 后再组间 fsum 改变原求值，测试包含额外舍入的反例。

该推导是有前提的工程依据，不是编译器/硬件形式化证明。任意新数值环境或
可变/动态求值语义都需要重新论证；失败即不给出剪枝或接受结论。

## 预算和证据

组件局部状态上限 256，准备上限 4096。当前原型预留并计入一次原状态检查和
每个表行的 `_satisfaction` 与取值 evaluate，各两次实际 evaluate；正常准备共
`2*(1+sum(local states))` 次。失败报告已尝试的准备调用；循环和预算预检在求值前拒绝。
完整全局穷举仅为研究参照，独立计数，不宣称满足未来求解器 4096 叶预算。

运行前保存源文件清单/哈希、协议、参数和全部 72 个规范；大源快照保存在
独立 results 目录。逐例保存输入、批准文件、完整表、映射/数值/解集摘要及
全局遍历摘要哈希；任何失败保留并使整体门槛失败。运行后再次核对源文件哈希。
并行工作进程只执行独立样例，计时不作串行性能比较。

附加测试覆盖 81/144 状态多选项、候选新增/原引用、相同数值的不同赋值、
缺失/循环/未知/非有限值、预算预检、无候选域和双重舍入。
G1 通过后可进入 G2 的证书与全局搜索开发，仍不能宣布 V519 整轮完成。
